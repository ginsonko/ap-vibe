# Agent 工作室完整交付计划与审查（2026-09-09）

## 目标与事实基线

用户要的是保留项目恢复和完整结构化档案的跨 Codex / Claude 信息中枢，以及可执行、可接手、有真实事件支撑的像素工作室。现有真实证据见 `AGENT-STUDIO-COLLABORATION-RESULTS.md`：串行、并行、自动等待、消息、返工、复查和重启回读已通过；不能由此推定跨执行器恢复、自动认领或收益已通过。

使用现有项目注册、档案、公共会话适配器、加密凭据和协调存储。不替换 AP 内核，不读 APV3 数据。配置新模型不修改用户的既有 CLI 全局配置；运行冻结角色配置版本。用户已授权本地实现、真实模型验收、媒体生成及合格后的发布。继续使用已配置凭据，凭据不进入文档、命令行或事件。

## 实施顺序与可验收结果

1. **执行器模块**：统一执行事件，保留 Claude 已通过行为；增加 Codex 本机登录与自定义 Responses 连接配置，CLI 实际支持什么就提供什么，模型名自由输入。新建、恢复、取消、未知请求保留、角色历史和档案工具均覆盖。Codex 不支持的协议给明确解释与可行路径，不悄悄改模型或走别的账号。
2. **共享任务现场**：公开会话目录、游标消息、项目档案章节入口和真实成果清单。按 provider + session_id 稳定标识；跨工具接手读取同一任务上下文，不抄私有推理。外部观察会话可读不等于可以终止其进程。
3. **任务池与所有权**：目标、验收、依赖、资源范围、owner、epoch、版本和运行历史持久保存；并发认领原子化。规划、拆分、自动领取、失败释放与接手复用同一任务。活动进程先确认停止/释放；不确定外部请求不重放。旧 owner 产物保留为候选，不覆盖新状态。
4. **沟通和调度**：定向消息、选择部分伙伴或广播，收件状态可查。空闲扫描由本地服务执行，不花模型额度轮询；自动接活可配置。模型/角色偏好可编辑，按同类实际验收样本形成能力记录，未知成本和能力保持未知。超时不直接等于低效，不无限互相唤醒。
5. **可理解的工作室**：地图/列表切换，新增编辑 Codex / Claude 角色、名字、连接、能力偏好和素材；任务入口、分配、接手、成果验收、消息均可操作。房间与移动/工作/交流动画来自已保存状态，关闭动画不影响执行。自定义素材及生成入口明确成本，原创像素素材保留生成和许可记录。普通列表、键盘、减少动态模式可用。
6. **真实验收和分发**：跨 Codex / Claude 继续同一任务；可并行代码任务 + 整合验收；原运行不可用后的接手；对比单 Agent 耗时、返工、质量及可知成本。浏览器逐项操作、干净安装、技能触发、项目档案保持、脱敏检查后才准备公开版本、中文说明书、非商用署名许可和推广素材。

## 对抗性审查与处理

| 风险 | 设计处理 | 验收证据 |
| --- | --- | --- |
| 接手等于重复计费/写外部系统 | 保留原请求状态和已知副作用；仅继续可验证未完成范围 | 不确定请求原样保留；真实本地中断恢复 |
| 两个 Agent 同时写同一任务 | 单 owner/epoch + 活动运行/资源冲突核对 | 并发认领一胜一冲突，旧 epoch 无法提交 |
| 监看误当控制 | 来源适配器与执行器分开；只停止本服务持有的进程 | 普通会话只读与托管取消分别验收 |
| 换模型悄悄用默认账号 | 新进程独立配置与凭据环境；保存请求模型/协议 | 实际执行启动事件及脱敏出口回读 |
| 全量上下文塞入、私有推理泄露 | 简报 + 按需公共输出/档案章节读取 | 提供目录并由第二工具按需恢复 |
| 假完成/假能力分 | 执行返回为待验收；显式结果及证据后完成 | 有真实缺陷返工样本；缺样本显示未知 |
| UI 动画驱动业务/假进度 | 地图只投影持久事件，业务不依赖页面存活 | 关闭页面任务继续；重放不重发任务 |
| 凭据泄露与配置漂移 | 现有加密存储，新运行配置快照，严格脱敏 | 日志/配置/事件检查，旧档案不变 |
| 过度设计导致迟迟无成果 | 沿现有模块逐条真实闭环，不造第二套认知系统 | 每一片有可用代码和最小代表性实测 |

审查结论：按上述依赖顺序实施。存量文案协作证据保留不重跑。当前 CUA 初始化失败且用户未允许独立 Playwright，浏览器验收仍须解决；该问题不妨碍实现其他部分。官方文档当前 HTTP 403，CLI 参数先以本机帮助与实测为证据，不能声称已核对官方页面内容。

## Codex 托管执行器实测补充（2026-09-09）

Codex CLI 与 Claude Code 的文件工具名称不同。Codex 侧使用 `exec_command` 和 `apply_patch`，不能在验收提示中要求 Claude 专有的 `Read`/`Write` 名称。API 兼容 Codex Agent 启动时使用独立 `CODEX_HOME/config.toml` 注册本地 AP-Vibe MCP，provider 密钥只通过 `AP_VIBE_CODEX_API_KEY` 环境变量传入；普通 local-login 会话继续忽略用户配置，避免修改桌面设置。

一次真实 gpt-5.6 API 兼容 Codex 运行（`run-d5f431bea1674b81a89d34bf9258b0d4`）已调用 `ap_vibe_context`、`ap_vibe_read(identity,status)`，并用 `exec_command` 在隔离目录创建和回读 `codex-context-check.md`，最终状态 `awaiting_review`。Windows 下 `apply_patch` 包装器出现 UTF-8/补丁尾行错误时，模型记录错误后改用 `exec_command`，不把模型自述当作成功证据。local-login 固定模型的工具可用性仍需单独核对。
