# 剩余角色动作与真实委托

## 目标和基础

九家族静帧与DeepSeek32帧动作已通过，保留原图集和历史ID，不重生成。用户要求其余伙伴也具有可辨识的像素形象、真实动作，并能把制作要求交给伙伴得到可以导入的成果。沿用既有PNG/JSON合同、媒体工作流原session、真实事件地图与素材导入API。

## 实施顺序

1. 恢复媒体服务绑定及原计划revision，确认旧生成全部已知状态，查当前可用图片配置和价格。原有未知账务请求不重放，新作品使用新逻辑节点并单次提交。
2. 先制作目前实际频繁使用的Grok、Codex/GPT及Gemini，再按同一合同制作Claude、Kimi、Qwen、GLM、OpenCode。每角色拆成16帧方向步态与16帧工作/阅读/交流/等候，独立检查后组合。真实帧次序、方向、手势、脚底及身份稳定是验收条件，不能用整体位移代替步态。
3. 保留完整参考与来源哈希；角色彩色部分不能被抠图误删。紫色角色使用可配置的绿色纯色背景或真实透明图；扩展已有提取器为可配置色键，保持旧DeepSeek结果不变。
4. 通过一条真实工作室“请伙伴制作外观”任务验收：新伙伴可发现本机媒体入口、沿持久生成请求取回成果、在自己的目录交付PNG/JSON与验收说明、登记并回读可选外观。必要工具缺失应补相同本机服务桥接，避免让模型绕读密钥或伪造素材。
5. 对每套实际图集运行尺寸/边界/透明/动作索引检查，查看联系表和动态预览。真实浏览器在桌面/手机选择、预览、应用并还原原配置，检查不同角色与地图的实际状态变化，不用生产项目做夹具。
6. 更新媒体节点与产物、项目档案、说明书和剩余能力状态；保留失败样本与原始生成，不声称未知许可已经获授权，不在公开仓库包含用户原图或凭据。

## 对抗性审查

- 原默认媒体连接未包含旧session，不允许据此重建；以已验证5679服务绑定和原session为准，更新器返回local_changes时保留用户修改。
- 同图多家族会削弱身份和动作一致性，因此按角色制作。主色相似不意味着相同角色；保留轮廓、发饰、服装和独有配饰。
- 固定洋红抠图会误删紫色头发与服装，须配置色键并验证前景色保留；不能为了通过技术检查裁掉辨识部件。
- 无权限读取模型连接时使用保存的配置ID，绝不在提示、图集、日志或成果放Key。请求结果不确定只对账，不自动重复。
- 委托任务必须产生真实PNG/JSON并实际被导入；准备提示词和好看的按钮不能当作委托完成。生成质量不好保留失败QA并有针对性修订。

审查结论：按以上顺序继续已授权媒体任务。视觉素材不能替代复杂协作收益或最终安装发布证据；完整产品goal仍active。
