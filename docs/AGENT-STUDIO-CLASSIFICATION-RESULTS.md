# Claude 项目归类：实现、验收与当前限制

当前补充（2026-09-10）：后续 Grok 首次完整建档及第二独立会话复用同一项目已经发生。第二会话生成了保留旧决定、事故和待办的增量文件，但上游中断前未调用提交；后来在同一持久隔离数据库中用 `ap_vibe_update_file` 恢复提交到第3版，即时及服务重启后均回读第3版和十维评估。这里证明真实归类、复用和保存补丁恢复，不证明所有普通任务都自动正确维护档案，也不把主任务恢复提交说成模型首次自行提交成功。

下文保留2026-09-08首轮的失败与接线证据；其“接下来”是当时的安排。当前协作、像素工作室与跨应用接续分别见对应结果文档。完整产品仍按内测清单验收。

## 用户会得到什么

普通 Claude 开始长期任务时，已安装的 Skill 会先查已有项目小目录，再按需读候选资料。确认属于已有项目就附加会话；确实是新项目则一起保存11章档案、十维评估和会话归属。一次性翻译、公告等无需建项目。新建需提供真实项目入口的稳定标识；多个新会话同时提交相同入口时复用先建好的项目，再读旧档案合并增量。

工作室托管任务沿用用户选择的项目。普通 Claude 和 Codex 可以读取同一项目的资料，但会话身份分别记录；Codex历史整理仍走原有来源归类流程。只读候选查询不要求先绑定项目。归属变化后旧收据仍可读，写入则重新获取当前项目收据，避免写错项目。

工作台的“Claude会话”现在显示已归类项目名称，未归类时解释何时需要建档。默认Claude安装器会更新自身Skill/MCP并保留原env、deny及其它hooks；已有普通终端仍只监看，不能用本次功能宣称可向任意终端发消息或停止它。
