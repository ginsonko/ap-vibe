# 安装实例一致性与新用户验收

2026-09-10。真实服务、任务与外观验收之后，检查安装入口发现：install.ps1接受ConfigDir，Claude接入携带该路径，但Codex的hook/MCP及Skill仍只查默认配置。选择非默认安装目录时，可能读取另一实例或报告未安装。

目标是让同一次安装的服务、Skill、hook和MCP始终使用同一份明确配置；默认安装保持兼容，不增加用户步骤。不改动其他插件、历史项目、用户凭据、已登记伙伴或保护数据。

实现：安装器向三个Codex安装工具传入实际config路径；客户端接受可选--config；hook携带该参数，MCP使用AP_VIBE_CONFIG_PATH。精确信任登记复用同一个hook命令构造函数，避免误认其他hook。两个安装后的Skill附本机installation.json，仅含配置和客户端位置，原仓库保留通用说明且不分发本机文件；恢复脚本读取同一安装描述。默认位置安装时保持原命令格式，避免无意义地改变已存在信任记录。

验收：先在隔离目录确认非默认路径与中文空格路径，原无关hook/全局指令和便携快照保存；启动两个不同配置的本地服务，调用生成的真实hook和MCP确认它们连接安装目标；停止隔离实例后用同一hook自动恢复并返回实际退避端口。真实全安装在D盘新目录与仅子进程的隔离Codex配置中完成，不借用用户登录凭据，不改变当前运行实例；官方CLI的MCP注册和hook精确信任也要回读。用原始HTTP状态、实例标识和进程身份对照，不能以安装输出ok替代闭环。

审查：显式--config优先于进程环境，环境优先于默认；配置不包含密钥；命令参数路径不得作为shell表达式执行；恢复描述只选择本机配置，网络仍限定loopback。多次安装只更新AP-Vibe的条目并保留备份；不把客户端配置错误当成模型不遵守Skill。测试只在新建隔离目录生成数据；重新安装默认实例不丢旧恢复文件。故障时有准确提示，不能静默回落到不相关的正在运行服务。

实际首轮安装在Windows PowerShell 5.1复现参数绑定错误：数组splat到另一个脚本把"-Action"当作位置参数值。改用命名hashtable参数；JSON明确以UTF8读取，中文脚本带BOM兼容系统PowerShell。失败收据和空安装目录保留，修后在同一个隔离安装位置通过正常重试接续，不改默认用户实例。
