2026-09-10。实际 Windows 安装已在独立中文目录完成，服务、Codex/Claude 接入和浏览器来自同一个安装实例。检查中发现的一键安装、配置传递和前端默认项目错误均已修复。本记录不代表整台新电脑、Windows 重启或全部产品发布均已通过。

后续状态：更早任务的分页、真实新消息锚点与草稿保留已经完成，见[历史阅读验收](SESSION-HISTORY-ACCEPTANCE.md)。后续 gzip 和按页读取也已完成，见[传输实测](JSON-TRANSFER-RESULTS.md)与[页面读取实测](WORKBENCH-PAGE-READS-RESULTS.md)。下文的体积和未测项描述保留当时边界，不应代替这些后续结论。

## 真实安装及升级

安装使用实际 PowerShell、Python、Codex CLI 和 Claude CLI，单独设置子进程的 Codex/Claude 配置目录，没有复制用户登录凭据，也没有改写主工作台的数据目录。原端口被主工作台占用时，独立服务自动使用另一端口。

16项安装检查覆盖实际 hook、MCP 注册与回读、对应实例恢复、停止服务后由原 hook 自动拉起，以及主工作台的进程和项目目录保留。重装随后完成13项检查：用户自定义 hook、MCP、Skill、全局说明、原配置/端口、便携快照和已经保存的档案备注保留，四类 AP-Vibe hook 各只有一份。测试备注明确标记为隔离验收内容，没有写入真实项目。

升级检查脚本最初误将 Codex 的 SubagentStart 写成 PreCompact；安装本身已经成功。保留错误检查记录后只修正读取验证，没有再次安装或重写备注。此前 PowerShell 数组参数调用失败属于实际产品问题，已经改为命名参数，并补充 UTF-8 中文路径及脚本兼容。

## 浏览器发现与修复

首次安装自定义项目后，旧前端仍请求不存在的默认项目，导致七个页面显示重新连接。现在先读取实际项目目录，保留存在的用户选择；没有有效选择时优先使用服务实际配置的启动项目。不存在的项目不发起数据查询，网络失败也不会被当成空目录。

| 用户操作 | 实际结果 | 证据范围 |
| --- | --- | --- |
| 冷打开独立安装 | 自动选择本实例项目，首页显示服务和监控在线 | 实际服务，无伪造项目响应 |
| 依次进入七个主页面 | 无页面异常和 HTTP 错误，空会话与缺少评分如实显示 | 部分异步子面板截图未等加载结束，不视为该表单的完整验收 |
| 浏览器记着已经移除的项目 | 自动选择有效项目，可读到升级前保存的备注 | 只改变本地浏览器选择，不修改项目归类 |
| 刷新页面 | 保留实际项目选择 | 独立实例回读 |
| 冷打开含多个项目的主工作台 | 选择服务配置的启动项目 | 不以目录首项代替当前项目 |
| 搜索当前 AP-Vibe 任务并打开 | 主任务只有一张卡片，进入正确标题和消息历史 | 子任务仍分别保留 |

主服务另验证220个来源的聚合投影：当前返回的最近128项中没有重复稳定任务ID；同一主任务的两个历史来源都保留，限定项目查询不混入其他项目。128项是当前前端读取上限，不代表全机总任务数。完整更早任务的界面分页仍需完善。

手动项目管理随后在独立实例实际执行7次界面写入：修改章节并恢复备注、新建、改名、归档、恢复、再次归档。原决定保持不变，第1版和恢复后的第3版均可回读，临时项目ID在各操作间保持一致；JSON导出文件已实际下载并解析。编辑器原先将删除按钮和输入框放在同一个隐式label里，导致文本域缺少正确可访问名称；已改为显式标签关联，并在真实浏览器逐字段检查。第一次标签失败没有写入；最终历史读取使用了错误路由的验证脚本已修正，只补回读，没有重放7次写入。

日期刻度、教师配置加载和默认消息底部也完成定向浏览器检查。教师配置打开时 API Key 为空且只提示已保存；加载完成前明确显示状态。消息历史上翻后的刷新保持位置，但该次刷新没有新消息，不能据此宣称本轮覆盖了新消息到达时的全部滚动行为。

## 剩余边界

主工作台的完整 state 响应仍约3.4 MB、一次测量约5.75秒。监控摘要已缩小为40,522字节（详细状态997,200字节），相同来源错误仍保留；不能把局部缩小称为全面性能问题已经解决。自动任务档案维护的长期遵循率、整机断电、多日运行、正式发布包和新手首次媒体入口仍在后续验收中。
