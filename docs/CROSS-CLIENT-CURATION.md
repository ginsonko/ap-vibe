# 用你常用的软件整理项目

从 v0.4.0-beta.3 开始，整理会话不再依赖 Codex。任务监看、项目记忆、逻辑观察、可选 AP 认知和像素工作室继续保留；本次扩展的是共同的项目整理入口。

## 三步开始

1. 打开“项目与记忆”，选择“整理最近 7 天”或“整理全部未归类”。来源应用默认全部，可只选 DSH、Claude、Grok 等实际发现的应用。
2. 在“由谁负责整理”选择执行端。本机 Codex、本机 Claude Code、已激活的 Claude 执行器伙伴可以后台整理；只有 DSH 等桌面客户端时，选择“交给当前软件（MCP / Skill）”。
3. 点击开始。后台执行端直接运行；当前软件模式显示接单说明，点击复制并发到原客户端。它会读取真实来源、提交档案并回读结果，工作台显示实际进度和档案版本。

例如：你只用 DSH，也可以整理本机 DSH 与 Claude 的会话；同一项目的会话可以合并到同一份项目档案。来源软件和负责整理的模型是两个独立选择。

已登记项目的更新可用“刷新项目档案”。它读取所属项目的各应用会话，只更新档案，不新增项目或搬动会话。模型用量按所选执行端的原有连接计算；AP-Vibe 不会自动替你选择收费伙伴。

## 直接发给当前软件的口令

> 请使用 AP-Vibe 整理最近 7 天所有已接入软件的未归类会话。先读取整理目录和真实公开内容，再按长期项目归类；同一项目复用已有档案，保留旧决定、事故、人工备注和待办。通过当前软件的 MCP / Skill 接单，不要求安装 Codex。完成后回读归属和档案版本，告诉我整理了哪些来源、哪些因信息不足保留未归类。

工具提供 list、prepare、read、submit 四个步骤。prepare 默认交给当前客户端，尚未调用后台模型。read 返回本次来源清单、真实上下文文件、旧项目档案、11 章合同与十维评估要求；submit 读取本地 JSON 提案，交给服务端统一校验和保存。没有原生 MCP 时，安装后的 Skill 可通过 native_client.py 调用同名工具。

## DSH Desktop

安装器为已建立的 DSH profile 增量登记原生 MCP，实际位置是 DSH_HOME/profiles/<profile>/cordis.patch.yml 的 insert 插件记录。它保留模型设置、其它插件、自定义 YAML 标签、注释和 settings.yaml，并保存原文件备份。

已打开的 DSH 若未自动加载新工具，重新打开客户端。尚未建立 profile 的新用户先启动一次 DSH，再运行 AP-Vibe 安装修复；安装结果会说明是已登记插件，还是仅生成配置材料。用户修改过 AP-Vibe 管理块时，安装器保留修改并提示需核对。

自定义目录可运行：

~~~text
python tools/install_native_extras.py --client dsh --home <DSH_HOME> --config <原AP-Vibe配置文件>
~~~

## 遇到中断

- 模型未登录或连接无效：在整理执行端选择其它可用连接，或交给当前客户端继续。
- 提案格式不完整：保留草稿和具体原因，修正后继续。已成功写回的项目可立即使用。
- 人工修改与并发更新：保留当前档案，重新读取后合并。原始客户端会话不被修改。
- 切换执行端：旧接单提案不能覆盖新任务；按当前说明重新读取并提交。
- 未发现会话：先到“会话 → 管理会话来源”核对实际目录。只整理当前适配器实际发现的公开来源，隐藏推理不采集。

DSH 本次调用由独立原生插件实例完成；写入正在运行的 Desktop profile 不等于已验证该窗口热加载。重新打开窗口后可用上述口令实测自己的会话。
