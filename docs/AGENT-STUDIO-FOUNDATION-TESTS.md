# Agent 工作室：基础实验与推进计划

日期：2026-09-08 · 关联：[主设计](AGENT-STUDIO-DESIGN.md) · [对抗性审查](AGENT-STUDIO-ADVERSARIAL-REVIEW.md)

状态：已按用户授权进入 P0。F02–F04 在 High 组合上已有基本工具纵切，F09 有真实接续结果；F08 仅完成正常回合边界补充，忙碌消息仍待实现。全部成功/失败、费用边界及后续缺口见[基础实测记录](AGENT-STUDIO-P0-RESULTS.md)。下表是完整实验计划，不表示所有项目都已通过。

## 1. 验证方法与实验产物

先证明最小拼图能工作，再建设依赖它的功能。每个实验回答一个明确问题，保留成功与失败收据。接口存在、返回 HTTP 200、画面在动、Skill 已安装，都不是端到端成功标准。

实验在专用测试项目/目录执行，不向正在维护的真实业务项目随意注入提示和文件，不重启用户活跃服务制造故障。故障测试使用独立候选实例和端口，由正式发现机制找到实际地址。数据库备份、日志和结果保存在不参与发布的验收目录。

真实模型实验可以使用用户已授权的银子 API 文本连接。先读取实际模型能力和价格信息，再选模型；缺价格保留未知并记录原因，不猜模型 ID 或便宜程度。Key 从授权凭据来源读取并交给进程，不写入测试源码、命令行、录屏或报告。每次收费提交记录关联 ID；超时先对账，不换 ID 重发。

实验收据至少包含：实验 ID、时间、产品/CLI/适配器版本、模型配置版本、实际请求模型名、任务与会话 ID、输入/成果哈希、过程公开事件、预期与实际、费用来源与未知、结论、失败恢复路径。原始敏感载荷仅按必要性保存在本机受限位置；公开报告只留脱敏证据。

结论统一为：通过、部分通过、失败、未测、不适用。部分能力失败不阻止无关能力测试；若它是下阶段的必要依赖，先修复或选择明确降级路线。

## 2. P0：基础拼图，先跑最短路径

P0允许在隔离候选中编写最薄的实验接线：进程启动、流解析、临时MCP入口和最小消息/任务记录，以验证真实协议。它们是可丢弃或后续重构的实验工具，不算正式产品模块。F11–F15使用这层最小接线验证合同；P1才将通过的合同工程化为完整持久服务与用户界面，避免出现“先有整个系统才能测试基础”的循环依赖。正式页面尚无对应能力时，F05/F15以实验列表和API回读验证归属，P3再验收正式UI。

## 3. P1：可靠最小协作与异常恢复

实施内容：任务/运行/消息稳定ID，执行与来源适配器分离，原子认领、持久outbox/inbox、依赖通知、成果引用、档案增量和普通团队列表。沿用现有项目/会话页面，不先重构整个前端。

| ID | 反例操作 | 合格行为 |
| --- | --- | --- |
| R01 日志尾部异常 | 读到半行JSON、未知事件、日志轮转、重复片段、乱序到达 | 等待完整行、保留未知类型、可恢复游标、去重；不能白屏或把旧消息重复入库 |
| R02 SSE/网络断开 | 流中断后恢复；服务返回429、5xx、401；测试一个长时间无文本但工具运行的任务 | 原任务保留，原错误可定位；429按服务提示退避，401不循环重试；无文本不直接杀进程 |
| R03 进程与服务重启 | 在保存结果前后、outbox发送前后分别中断独立候选daemon | 已确认数据存在；未确认可恢复；通知不会触发重复验收，未完成不显示完成 |
| R04 认领失联 | owner失联，lease过期，但原工具仍在运行；旧owner稍后回报 | 先核对运行，不自动双执行；旧成果保存候选，当前状态由epoch保护 |
| R05 外部结果未知 | 用可控测试端点模拟“已执行但回复丢失”的有副作用请求 | 按请求ID查询状态；不支持查询时显示待核对，不盲重发；不做真实付款故障注入 |
| R06 停止与交接 | 停止一个托管任务，其余本机任务同时运行；包含子进程和未提交文件 | 只操作有创建标识的目标运行树，保存checkpoint和修改；接手范围准确 |
| R07 同文件/共享资源 | 两worker改同一文件，并试用同端口/测试数据库 | 发现冲突并串行/隔离；不因worktree独立误认共享资源也独立 |
| R08 并发档案 | 两工具基于相同revision改章，同时用户改其中一章；模拟提交回复丢失 | 重读合并、保留人工和历史；同请求可回读，不覆盖或重复添加；十维未知不造分 |
| R09 关闭/删除角色 | 有待收消息时归档Agent；模型Key失效或轮换；角色改名 | 历史消息成果可找，待办可转交，稳定ID不变；不偷用另一Key继续 |
| R10 动态依赖与消息风暴 | 最后一个worker完成同时新增子任务；两个Agent连续互发相同建议 | 旧generation不早唤醒；重复聚合、同话题有明确决策者，无自激循环 |
| R11 Skill漏调用 | 选择一次不主动维护档案的托管回合；再测未装hook的外部终端 | 托管终态识别缺项并补收据/排待办；外部会话诚实标记，主体成果正常交付 |
| R12 磁盘/队列压力 | 候选实例模拟空间不足、存储写失败、事件持续增长 | 不确认未持久结果；保留错误及可恢复入口；增量读取有分页、保留周期和检查点 |
| R13 查询开放与写隔离 | 新会话、无归类、旧身份读取不同项目；尝试将更新送入错误project_id | 授权本机数据可查询且标来源；串项目写明确失败并保留patch，不能用错误身份警告挡读取 |
| R14 脱敏与指令注入 | 来源文本含伪造系统指令、密钥样式和命令字符；检视日志/备份/导出 | 来源作为数据，不能授权动作；密钥不外泄，路径参数不触发shell执行；普通Markdown仍正常显示 |

故障在可控候选环境发生，复用同一组真实链路收据加少量定向故障注入。无需每次修改都重跑全部付费矩阵。R03/R04/R05/R08 是恢复正确性的重点，不能用UI提示代替底层行为。

R13已有本轮反例：同会话存在当前项目关联和另一个来源容器时，bootstrap允许写入，update仍返回membership_changed，重新bootstrap无效。将此例提前到F10的基础维护验证：两端使用一致的权威项目关联，旧来源标记不能无穷要求重新bootstrap；真归属变化需要重新解析和保留patch。修复后用正确项目成功回读、错误项目写入仍不落库两条证据确认，不能以去掉全部写入检查算完成。

## 4. P2：扩展模型并判断是否真的划算

在最小可靠协作成立后，从用户服务的实时目录选择：一个质量基线、一个低成本候选、一个不同能力侧重的候选。模型名由当时目录决定，不把本文件示例当可用模型保证。每个新增组合先复用 F02/F03/F04/F09/F10，涉及模态再补图片输入与工具结果测试。

能力矩阵记录服务、模型、协议、CLI、工具、流式、恢复、AP-Vibe、图片、价格来源、日期及失败原因。发现新增参数时只扩大必要测试，不因一个组合通过就声明所有同名/同厂模型可用。

### 4.1 同题对照设计

第一轮选择六类真实常见需求，每类两道互不泄漏答案的任务，共12道：

| 类别 | 示例 | 关注点 |
| --- | --- | --- |
| 小修改 | 单页文案或一个配置字段 | 团队是否反而制造延迟；默认应倾向单Agent |
| 可并行开发 | 搜索+导出，附明确接口合同 | 两worker是否节省墙钟时间且整合正确 |
| 串行排错 | 复现接口错误→定位→修复 | 不乱拆前因后果，不派多人重复排查 |
| 资料与实现 | 阅读规范→实现校验器→核验反例 | 来源和逻辑不因传话丢失 |
| 多素材任务 | 给定图片/文本，输出结构化整理与页面 | 模态能力与上下文选择真实有效 |
| 历史接续 | 新会话根据项目档案继续旧需求 | 少重复解释、保留旧决策、档案更新质量 |

每题分别运行单Agent与最小团队，使用同一初始项目快照、需求和验收标准；随机交替运行顺序，避免高峰时段和缓存倾斜。记录不同模型/角色配置，禁止把上一轮答案给下一轮。每次独立保存失败，不能删失败样本只挑成功截图。

该24次运行是发现明显方向问题的初始样本，不足以宣称长期统计优势。有明显异常/高方差或两组接近时，再对有意义的类别补重复；不为了一个总体百分比无差别增加成本。执行前登记当时价格估计及总预算偏好，当前用户已授权模型实验；面向发布用户默认显示计划花费并允许自设预算。

统一记录：

- 质量：验收通过/失败、严重缺陷、返工轮次、结果是否保持原需求；评审尽量隐藏运行方式，运行收据补足主观评价。
- 耗时：用户提交到可验收成果的墙钟时间、等待时间、规划/执行/通信/整合/验收时间；并行不能只相加worker耗时。
- 成本：所有请求输入/输出/缓存用量、模型费用、失败和重试费用、可取得的订阅用量。不可取得时明确未知，不换算虚构金额。
- 体验：需要用户补充或纠错的次数、步骤数、不可解释等待次数、恢复时丢失多少上下文。
- 维护：档案有效章节与新增事实、十维分析质量、人工内容是否保留、重复写入或漏更新。

决策规则提前固定：严重越权/串项目/成果丢失/重复有副作用执行视为该方案失败；团队必须先满足同等质量，再比较成本与时间。按任务类别分别给出单Agent/团队建议，用户可选择省钱/速度/质量偏好，不凭总体平均掩盖某类倒退。只有实际数据支持时才发布相应收益表述。

### 4.2 可选 AP 增强对照

先跑不使用外部教师的确定性协调基线，再以相同初始项目状态和任务集比较 AP 建议开启。记录建议、采用、原因、结果及教师额外费用。学习训练样本与最终验证任务分开，避免对已见题调优后宣称泛化。

以既有 AP 运行时真实对象检查感知/SA/感受慢量/行动器/节点/范式：注册可查询、输入有来源、状态变化有事件、行动回读可关联、关闭教师后基础功能仍成立。没有足够证据的项目状态保持未测；不得用模拟分数表示认知成长。

若增加调用但质量/成本没有可见改善，继续保持实验可选，不把基础协作绑定在 AP 上。评价可能是“某些任务受益，另一些无收益”，这也是有效实验结果。

## 5. P3：像素工作室及小白验收

前置条件：团队普通列表已经可以真实交付和恢复；状态事件合同稳定。先画信息布局与角色图集规范，再生成原创素材候选，然后用真实任务驱动本地动画。

建议布局：顶部一句当前目标和“谁在做什么”，中间工作室/列表切换，右侧选中角色的任务与消息，底部折叠团队时间线。手机端先任务列表，地图为可选全屏视图。用户看见失败原因和下一动作，无需读内部状态码。

逐按钮真实浏览器验收至少包括：

| 操作 | 用户实际要看到什么 |
| --- | --- |
| 添加/复制/编辑Agent | 名称可重复但对象独立；字段保留；Key不回显；配置生效时点明确 |
| 测试连接 | 加载态、费用提示、实际能力及可操作错误；未知模型能输入 |
| 分配任务/补充要求 | 一个主按钮完成派发，任务版本及接收状态可回读 |
| 查看角色/公开对话 | 有标题与所属项目，Markdown可读，长对话有界；底部跟随/历史不跳转 |
| 发消息/取消未发消息 | 对应收件人正确；已投递和已回复分开，未发撤回有收据 |
| 请求帮助/交接/暂停 | 明确当前状态；只作用于目标任务，成果保留；不可立即暂停解释当前外部步骤 |
| 查看成果/验收/定向返工 | 文件/差异能打开，版本一致；返工只包含真实未通过点 |
| 地图/列表/减少动态 | 信息等价，键盘可操作，隐藏动画不影响消息与业务 |
| 角色改名/形象/归档 | 历史归属正确；未知图片和加载失败有静态回退 |
| 项目档案/当前与全部更新 | 保留原工作台入口，11章/十维各自准确，不因新页面重造维护路径 |
| 帮助/AP实验入口 | “什么时候用、怎么用、示例、费用、失败恢复”清楚可见 |

至少覆盖8种人物：完全新手、已有Codex用户、只用Claude用户、低成本模型用户、已有多个长期项目的人、仅一次性小任务的人、网络不稳用户、键盘/减少动态用户。拿同一说明和成品操作，不事先给测试者解释隐藏入口。

记录首次成功任务步骤数、完成时间、误点、需要解释的地方；哪里要多次“准备/确认/再开始”就回查是否可以合并。没有必要为了验收存在而新增审批流程。

性能先测用户本机真实规模，再以测试事件回放检查增长量。UI性能回放仅证明渲染，不证明模型协作。目标为交互无明显卡顿、长消息分页、后台不持续渲染、重要状态最终可见；初始响应/延迟目标按基线记录后定，不伪造精确SLA。事件日志滚动与保留不能删除未确认消息、在途任务和必要恢复依据。

## 6. P4：迁移、发布与内测交付

现有AP-Vibe基本版仍按原内测清单推进；Agent工作室可作为关闭默认功能开关的预览模块，独立交付能力表。未实现能力不出现在正式宣传的“已经支持”清单中。

发布前检查：

1. 旧数据迁移前有备份；项目、旧revision、人工字段、会话关联和运行成果不减少；模块关闭后原工作台仍能用。
2. Windows干净用户环境：缺CLI、未登录、首次安装、端口占用、路径有空格/中文、安装重跑、卸载/升级均有真实结果。自动安装不绕过用户账号登录和宿主权限策略。
3. Codex与Claude接入分别验证自然语言启动、按需读取、终态维护、服务离线拉起及实际前端地址。不能从一个宿主通过推定另一个。
4. 新执行器不会接管任意普通终端；能力不足时界面退化清楚、现有工作继续。
5. README、许可、第三方CLI/素材声明与实际发布包一致。AP-Vibe当前目标许可为个人非商业使用、允许个人二开并注明来源；这不是OSI开源许可。第三方模型/CLI条款单独适用，分发方式发布前核对，不捆绑用户Key或未经允许的CLI二进制。
6. 发布目录排除私人会话、凭据、数据库、验收原始载荷、缓存和个人连接配置；推荐模板只有公开模型信息与可编辑说明。
7. 安装口令/宣传图必须带真实仓库、版本或稳定入口、用途与自动安装步骤；图给干净新会话后真实装到能看到任务。视频来自实际可用流程，不能用动画替代未成功的工具调用。
8. 给内测者明确支持组合、已知限制、脱敏反馈与回滚入口；不要求内测者先理解所有协作模块。

内测可交付条件是：公开声明的每条主路径都有真实完成收据和相应故障恢复；无已知会导致丢成果、串项目、重复外部动作或无提示阻塞的严重问题；剩余非阻断缺口有具体说明和回退。不能保证“开放世界从不出意外”，应保证意外可看见、成果可恢复、不会无证据宣称成功。
