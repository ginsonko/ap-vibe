# 一次真实工程对照的结果

本次让单人和分工团队分别完成同一份像素素材目录检查工具。双方有相同原始资源与接口合同，运行后由独立伙伴检查真实文件和反例；发现问题允许合同内一轮返工。所有网络中断、恢复和失败保留。

2026-09-10 最终结果：两支均未完全通过。团队两个模块已独立通过，整合修复后通过主任务 18 组共同检查，但独立检查发现两个额外边界问题：输出路径互为父子会留下部分结果，括号中的绝对路径没有完全脱敏。单人最终也有两个未修复问题。团队检查者确认原始八个输入文件的 SHA 完全未变；49 项作者测试通过，独立 42 项检查 40 通过、2 失败。

该样本说明系统已实际完成分工、依赖等待、自动派发独立检查、发现缺陷后返工、断线保留成果及继续检查。它也说明“执行成功”与“作者测试通过”不能替代独立产品验收。配置内返工次数已用完，两个原任务保留需要修改状态，不把它们改成通过，也不追加实验来制造更好看的对照。

| 口径 | 单人分支 | 团队分支 |

| 执行次数，含失败、恢复和检查 | 7 | 11 |

执行时间相加包含并行时间，不能当完成耗时；墙钟跨越中断和等待，不是受控速度指标。第三方模型的 CLI 估计可能不适用，不能作为真实账单。主任务的实现和复查成本未计入上表。本次没有证据宣称团队普遍更便宜或更快，也没有证明所有工程都能自动达到验收标准。

下一产品改进来自实际遗漏：运行中的伙伴须能在正常工具阶段收到新增帮助消息；前端须清楚展示需要修改、检查依据及继续入口。原实验文件和完整收据保存在本地验收目录，公开说明不分发用户工作区或配置。
