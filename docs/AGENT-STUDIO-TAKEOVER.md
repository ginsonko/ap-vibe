# 伙伴失败后的接力与恢复

AP-Vibe 把一个目标保存为持续存在的任务，每次模型执行只是这条任务的一次分工。连接失败时，已经写出的文件、公开进展、原始错误和检查报告仍然保留。

## 正常使用

在“Agent 工作室 → 任务池”新建任务，写清目标和完成标准，选择可接任务的伙伴以及一位独立验收伙伴，再开启自动领取。候选可以分别使用 Codex 和 Claude Code，也可以让不同名称的伙伴使用同一模型。模型与外观分别配置。

运行失败后，服务会核对执行器是否确实退出，再尝试其它候选。接手者在新目录获得原任务的公开成果和接力资料，先读取、核对，然后继续剩余工作。原目录不会被本次接力覆盖。网络请求结果未知时，进程退出不能证明供应商没有计费或没有执行外部动作；接手者必须先核对这些结果。

新任务的“候选都失败后额外恢复次数”默认是 1。所有候选都试过后，允许最后一位仍可用的伙伴再读取现场继续一次。填 0 可以关闭；数值可以自行调整，额外运行可能产生新的 API 费用。计数持久保存，重启不会清空。旧任务没有此配置时保持原行为，不因升级自动重新执行。

| 实际情况 | 工作台如何处理 |
| --- | --- |
| 某位伙伴明确失败，执行器已退出 | 尝试下一位候选，保留原成果和错误 |
| 连接断开，但本地进程已实际退出 | 可从已保存现场接力，原外部请求仍标明未知 |
| 候选全部失败，额外恢复次数有剩余 | 最后一位可用伙伴发起新的恢复运行，读取已有文件 |
| 用户取消或运行是否结束尚无证据 | 保留现场，不自动重新启动 |
| 次数耗尽 | 显示原因，可编辑候选与配置，或“保留成果并重新分配” |
| 作者返回完整结果 | 自动交给所选独立验收伙伴检查实际文件 |
| 检查要求修改 | 按配置交给最近一位实际作者修订，然后再次检查 |

“任务接力记录”可以打开每次分工的过程与成果。成果文件默认优先显示实际交付；接力清单、运行信息和 Skill 资料位于“运行与接力资料”分组。模型报告是具名判断，不能取代重要业务结果的事实验证。

## 已验证的事实

2026-09-09，真实 `gpt-5.6-sol` Codex 执行器读取项目上下文，并创建一份尚未写完的中文说明和随机 UUID 文件。只作用于本次验收的本地代理随后返回 503，Codex 确认退出。后台自动启动 Claude Code 执行的 `grok-4.6`，读取现场、保留 UUID 并完善文档。

第一次 Grok 接手在写完文件后遇到真正的供应商断连。当时版本在候选耗尽后停止；通过工作台编辑候选并点击保留成果继续，新的 Grok 运行回读已有文件，独立检查伙伴最终逐项接受。实际磁盘校验确认：原 Codex 草稿没有被覆盖，UUID 在三次分工中逐字节一致，最终说明与接续报告存在。这条样本包含一次页面恢复，不能描述为连续两次故障都全自动。

该样本促成了上述可配置的额外恢复机制。随后一个新的真实 Claude/Grok 任务在写出半成品后遭遇测试代理 503，执行器退出，后台自动发起一次恢复。新运行继承同一 UUID，完善正文并通过独立检查。全过程没有点击恢复按钮；原草稿及失败请求保留。该样本的文件哈希、两次作者分工和独立报告已回读，证据位于维护者本机的 `.local-acceptance/ACCEPTANCE-20260909-claude-auto-v3-cross-harness.json`。这是受控本地连接故障下的真实模型流程，不能代表所有供应商异常。

本地定向测试覆盖退出收尾竞态、仍在运行、取消、重启回读、同时调度、候选耗尽、额外恢复次数及原作者优先。真实浏览器验证了接力入口、原运行和新运行的文件、桌面与手机布局，以及编辑候选、继续分配、恢复次数 0/1 的保存回读。

这不证明多 Agent 更省钱或更快。跨执行器样本中，两次成功 Grok 运行的 CLI 估算合计 3.05065 美元；两次失败运行缺少完整费用，供应商最终结算也未知，不能把该数值当完整总成本。模型兼容性会变化：此前可用的 `gpt-5.6` 在首次实测时被供应商拒绝，后续明确选择目录中的 `gpt-5.6-sol` 才完成写文件，系统没有静默替换模型。

## 仍需推进

普通桌面会话中途退出后的跨应用接续、更多真实网络/进程异常、多个任务的能力分配与效率对照、完整像素动作和地图、干净安装及发布仍属于后续验收范围。独立成果目录也不是操作系统沙箱。
