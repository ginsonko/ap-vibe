# Claude 会话与项目档案：本轮真实验收

2026-09-08。承接[基础实测](AGENT-STUDIO-P0-RESULTS.md)与[接入计划](AGENT-STUDIO-CLAUDE-INTEGRATION.md)。当前仍是实验预览，不能据此宣称自动团队和正式发布完成。

## 已经能做什么

- 工作室的“Claude 会话”自动发现本机普通 Claude Code 公开日志，按真实标题或明确标注的首句摘要区分，显示目录及消息。支持增量、历史分页、文件截断恢复、滚动跟随；读取隐藏推理、附件内容、工具参数和工具结果正文不在范围内。
- Skill 正文等 `isMeta` 注入记录不会被误显示为用户发言。缓存中的活跃标记会随时间过期，不能把最近有输出冒充仍在执行。
- 托管 Claude 显式加载项目 Skill，复用 context/read/update/feedback。11章协议由同一个规范生成，项目资料按需读取；结束前增量维护并回读，不把本次笔记覆盖整个项目。
- 普通 Claude 的安装器保留已有设置，安装用户 Skill、MCP 和启动/提示/收尾 hook。真实 session_id/cwd 从hook传入，服务停掉后可以由启动hook恢复并给出实际地址。一次性问答不创建项目，收尾提醒不无限重复。
- 每个托管 MCP 绑定启动它的工作台实例，隔离测试不会误写默认工作台。任务页的档案状态来自真实 MCP 结果：写入成功和全部更新章节回读是两件事，均不等于内容质量自动通过。

真实模型：`gemini-3.8-flash-high`，通过已授权服务运行。本轮初始任务18回合，267.890秒；修正回合12回合，165.615秒。后者续用了已有上下文，二者不是可公平比较的成本基线。CLI报告的token与美元估计不是供应商结算账单。没有同题单Agent对照，**不能宣称省钱或提速**。

首轮缺陷已保留为“需要修改”，修正成果经Codex读取真实文件、档案和MCP回读记录后验收。没有把失败历史抹成一次成功。全部本机收据、日志和凭据排除在公开发布内容之外。

## 安装与使用

Windows主安装器检测到Claude Code后会自动接入；只使用Codex的用户可以传 `-SkipClaude`。已有AP-Vibe服务的机器也可以运行：

```powershell
python tools/install_claude.py
```

安装后新开或恢复Claude任务。工作台 → Agent工作室 → Claude会话可看普通会话；工作台派发的任务在“任务与输出”查看。已有普通终端当前只读监看，不提供假发送/停止控制。自定义Claude目录可用 `--claude-dir`；独立AP-Vibe实例可用 `--config`指定其配置，地址仍必须为本机loopback。

长期项目按需查资料并在结束时更新。现已增加Claude项目目录/归类工具及完整建档事务，保留原本Codex整理流程；本地真实CLI接线已验，远端模型本轮返回空答案或超时，自主新建质量仍未通过。详见[归类实现与验收](AGENT-STUDIO-CLASSIFICATION-RESULTS.md)。
