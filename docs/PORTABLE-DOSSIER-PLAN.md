# 把项目档案带到另一套工作台

用户目标是带走项目背景、旧决定、事故、待办和十维理由，导入后能继续按章查询。检查发现旧便携包只有恢复基线和活动，没有当前项目档案；仅增加上传按钮无法满足恢复需求。

实现沿用现有便携协议、内容校验、持久草稿和幂等确认，增加可选 `payload.documents` 当前档案快照，保留章节来源和原版本信息。导入创建独立项目和本机第1版档案，不绑定旧机器会话、不覆盖现有项目、不把原评分升级为新的实测。旧版本导出包仍可读，并说明其中没有结构化档案。历史决定与事故在当前章节中完整保存；完整逐版审计库、代码、凭据、所有会话和正在运行的任务不属于便携包。

页面提供“导入项目”入口：选JSON、填写此电脑的项目目录、预览章节/十维/活动数量、创建并打开项目。失败保留同一请求与草稿，再点只重试同一个操作；正在提交期间禁用改选。完成后按需读取新项目。没有档案的旧包要在预览中明确提示。取消只关闭预览，不修改已有项目。

对抗审查：源档案必须经现有hash校验后导出；包内所有内容经过脱敏与包hash覆盖；用户路径属于接收端元数据，不能改动源内容身份。导入档案写入在独立事务中，使用bundle hash产生固定request_id，进程在阶段间退出后重试不能产生第二版或覆盖人工改动。预览与确认复用相同验证，格式错误要在创建项目之前返回。既有导入目标冲突必须保留原项目。默认目标名称是副本名，防止目录中同名难辨。

验收：真实模型创建的设备登记项目导出，在独立服务数据目录通过浏览器选择包、预览、导入、查看11章和十维；检查旧决定、事故、用户备注、未知分数及已知未实现项；重启后再次读取。定向负例包含损坏JSON/hash、缺档案旧包、重复确认、阶段间中断恢复和目标冲突。主工作台演练项目只读，不由主任务改写其档案。

实际浏览器追加发现：初次项目目录返回时，项目页ErrorBoundary按project_id重挂载，用户提前展开的导入区会消失。导入为全局操作，项目页容器保持稳定；项目档案和人工管理仍按project_id隔离，避免把前一项目编辑草稿带入另一项目。此修复需要在初次加载期间直接点击导入验证。

第二个真实断点：前端导出和导入各自JSON.parse/stringify会把1.0改为1，破坏服务端的包hash；大整数也可能损失精度。两端改为原始JSON文本传输，保留原始数值，由服务端解析、校验，再附接收端目标元数据。没有放宽内容hash核验。旧前端已损坏的文件应从原工作台重新导出。
