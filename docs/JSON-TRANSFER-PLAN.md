# 大页面数据的传输压缩

本机实测state约3.59MB，data约567KB，主要内容是已有认知帧、历史观察和审核证据。当前先用标准HTTP gzip协商缩小传输，完整JSON内容和原API保持。浏览器请求声明接受gzip时压缩，CLI未声明或明确q=0时保留原字节。小响应不压缩，避免额外开销；压缩后不更小时仍发送原内容。使用标准库低等级gzip，输出长度和Content-Encoding准确，Vary保留协商语义。

对抗审查：不截断、删字段或改变认知证据；不可把网络体积缩小说成渲染/查询时间同比变快。POST持久化和幂等不受影响，不压缩SSE流，也不改变网关模型请求。响应仍no-store。本机API没有向跨站开放读取；不含明文密钥的既有规则仍适用。尊重identity更高权重和显式拒绝gzip。用真实HTTP测试协议、解压后字节一致、中文、错误状态和断线；现场只有无在途托管任务才正常重载。

验收：本地HTTP对相同固定负载分别声明identity/gzip，解压后字节相等，Content-Length一致，协商拒绝可用。再对现场state/data做同时间窗口内容及传输体积回读，浏览器实际页面可读。后台查询和DOM成本仍需要后续按页面读取优化，不在本改动中假称已解决。
