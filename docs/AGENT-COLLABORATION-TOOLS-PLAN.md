# Agent 自主分工工具与真实验收方案

日期：2026-09-09。前置状态：animation checkpoint 最终追加、档案 revision42。

## 目标与交付

在现有 StudioTasks、托管执行器、消息存储和独立裁决链上，让 Codex 与 Claude 伙伴能按需看同伴、看任务、创建可执行分工、认领空闲工作、移交已停止工作、广播信息和读取真实成果。维持每个 Agent 的单执行约束，任务历史与原成果不丢失。普通会话也能使用这些入口，没有新增读取鉴权或项目绑定门槛。

本阶段交付：共享 MCP 工具、共享协作 Skill 参考、运行器和安装器完整接入、真实 HTTP 合同验收、一轮真实规划/工作/独立验收链。像素动作完成度、普通跨应用接续、费用能力比较和整体发布仍独立验收。

## 方案

1. MCP 暴露现有任务 list/save/claim/release/archive，消息 broadcast，伙伴公开目录及状态，按需运行输出和成果。任务列表支持项目筛选、分页、小目录和精确回读，不能因最近200项窗口藏住旧任务。伙伴角色偏好属于配置，运行/裁决是事实；不把偏好当能力评分。
2. 所有任务写入使用原稳定 request_id 与版本 CAS。归档增加兼容旧 UI 的可选幂等身份；重试同请求返回原回执。验证候选真实存在，避免成功建出永远不能派发的任务。已有任务状态机负责派发、独立验收、返工和故障交接，不另造调度器。
3. 托管身份用于归因，claim 的 agent_id 是目标伙伴，不能被自动改成规划者。忙碌伙伴通过 eligible_agents/auto_run 给自己排后续任务；当前回合退出后调度器再启动。release 只操作已确认停止的任务；不能把它描述成强停运行中任务。继续沿用原进程停止检查。
4. 统一 Claude allowedTools 与 MCP 工具目录，避免新增工具展示但实际拒绝执行。生成插件、普通 Claude 安装与 Codex Skill 同步带上共享协作说明。工具失败修正参数；响应不确定先回读原任务/回执，不重建逻辑任务。
5. Skill 说明：先确认用户目标与授权，读取当前伙伴和项目任务；有独立可验证工作才拆分；写具体交付物/标准/依赖/资源；配置独立验收人。子任务不得扩大为再规划整个项目或无穷递归拆分。通信只发送有作用的进度/冲突/交接，不定时闲聊；消息已保存不等于对方已读。成果依赖来自任务完成和验收记录。

## 对抗性设计审查

| 维度 | 风险 | 处理与验收 |
|---|---|---|
| 范围 | 新工具暴露却绕开现有生命周期 | 直接调用既有服务方法，任务与运行仍一对多 |
| 并发 | 规划者给自己再启动/多个模型抢写 | 保留 busy、版本和资源冲突检查；自排队实测 |
| 恢复 | 响应丢失重复启动或归档报错 | 原 request_id 重试、持久回执、重启回读 |
| 数据 | 列表截断漏掉任务、角色秘密泄露 | 分页小目录；仅公开资料与状态，不返回密钥 |
| 质量 | 执行结束冒充完成、自己验自己 | 独立裁决、真实文件检查，未知保留 |
| 成本 | 随意递归调度和无限轮询 | Skill 限定授权范围；实验显式有限任务/回合，不设置全局调用次数硬上限 |
| 安装 | Skill 引用或允许工具遗漏 | 同源工具名称、参考文件复制测试、实际运行工具事件 |
| 体验 | 操作回执只有ID，不知后续怎样 | 返回原任务状态和读取入口，说明排队/派发/验收的实际含义 |

结论：按此方案实施，已有模块足够承载本阶段；普通会话接续与能力评分尚不在这份证据范围。

## 验收

- 隔离真实 HTTP/MCP：创建/回读/筛选分页/抢占冲突/候选错误/归档幂等/广播去重，保证没有模型调用。
- 插件/安装器/Codex 同步引用与工具可执行合同；保留现有文件与未知用户配置。
- 新真实请求：规划伙伴从任务目录读取、分拆两项可独立交付工作，登记依赖汇总和独立验收，保存分工文件和选择依据；工作伙伴读取公开消息并产出文件，验收人给出真实裁决。捕获运行与任务ID、工具事件、文件哈希、完成先后与最终读回。断点只修首个坏链，不伪造模型提交。
