# 更早会话的查询和实时阅读入口

现有首页和会话页只展示监看投影最近128条任务，而本机已有220条来源。Agent可调用的统一 sessions API 已支持分页、搜索、Codex/Claude筛选及公开消息前后游标；前端不应让更早记录只能退回终端寻找。

在会话页增加“查找历史 · Codex / Claude”入口，复用统一目录和读取接口。目录按页查询，可搜索标题、任务编号与工作目录；切换筛选重置页码、取消旧请求，错误保留最后一次同范围结果。使用真实来源ID读取，不按标题猜项目，多个来源的项目和可读状态要保留。最近监看视图保持原工作方式，明确是最近已读任务。

历史阅读初次加载最新公开窗口；可向前读取，继续用游标轮询新消息。停在底部跟随，上翻后保持可见锚点；源文件轮换时清除旧generation避免拼接错误文件。Codex复用已有消息发送器，普通Claude现有终端仅监看并提供继续命令，不能伪装支持向既有终端写入。来源文件缺失、空窗口和局部坏记录要给具体可理解说明，不删除记录。

对抗审查：目录分页与消息分页不同；同名不同ID不能混合，同一ID多来源不能丢来源；显示范围要区分已登记Codex与可发现Claude上限；不扫描或发送私有推理。不重复实现会话存储、MCP或调度。消息组件复用现有有限高度与锚点逻辑，新增历史页时不能计为新消息，Claude发言不得标成Codex。

验收：真实浏览器搜索一个第一页之外任务、翻页、打开Codex/Claude记录与向前读取；查询迟到/失败可用本地网络延迟注入检验。新消息跟随使用本主任务的一条实际公开进度消息，同时验证底部和历史位置两种状态。检查桌面和390宽度、无模型启动、无服务/归类/档案变动；已有后端接口无需重启当前工程整合任务。

## 实际浏览器发现与修正

冷开页面后先进入历史页，项目目录稍后返回，App按projectId重建整个PageErrorBoundary导致全局SessionsPage丢失archive模式。这是用户真实会遇到的操作中断，不能通过测试等待初始项目加载掩盖。修正为会话页的组件身份只由页面决定，仍按真实session/source隔离消息；项目相关页面继续按projectId重建。验收保留冷开立即操作路径，并在目录返回后确认查询与翻页不被重置。侧边栏尚未取得项目时显示读取中，不能误报自动监控关闭。

第二个现场断点：主任务原日志373MB，公开读取每次2MB窗口，有多个只含工具记录的片段。向前阅读改为顺序略过空片段，找到公开消息或文件开头即返回；一次约10秒后让出，仍保留可继续的before游标，切换/取消立即停止。没有把工具/私有推理展示为公开消息。缺失历史日志仍保留目录，显示具体原因，不把它当作整站离线。

截图复核：390宽度的底部导航会挤住Claude继续按钮，历史详情高度需扣除顶栏和底栏，卡片内部保持可滚动。另Claude日志把tool_result装在user记录内，公开投影应保留“工具”身份；仅纯工具记录改为tool，含真实发言的混合记录保留原说话者，不依据文本猜测。该后端变更待托管任务全部空闲后正常重载，再对真实Claude记录回读验收。

草稿保留：会话页和历史页的未发送消息使用App已有内存草稿表，键改为应用+稳定会话ID，同会话不同来源共享草稿，不同会话互不覆盖；切换查询/近期模式仍保留。不会创建新的本地持久存储或自动发送。浏览器以两条真实Codex任务验证往返保留、正常与历史视图复用，禁止实际POST。
