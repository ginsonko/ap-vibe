# 普通托管任务的本地执行能力

## 真实缺口

准备复杂工程协作验收时核对执行器发现：普通Claude托管任务只提供Read/Write/Edit/Glob/Grep/Skill，Bash只在选择媒体扩展时开放。这使普通模型无法运行生成的代码或测试，容易把静态自述当可用成果，也让用户被迫选择无关媒体工具。

## 设计与对抗审查

将Claude原生命令工具纳入基础工具集，沿用每运行独立成果目录、冻结模型配置、明确用户任务范围和现有凭据处理。媒体扩展只控制媒体Skill/MCP的挂载。Codex执行器已提供命令运行，本项使两者具备同类工程基础能力。

本机命令不是操作系统沙箱，原Read/Write同样没有这种保证。明确要求代码/测试输出限本任务目录，项目资料按需读，不扩大用户目标或重复外部请求。用户已授权托管本地工程任务，不增加弹窗或按模型白名单放行。未来真正的隔离执行属于独立产品能力，不以一个工具过滤列表声称已经实现。

验收先核对普通及媒体运行的CLI工具集合、凭据不入参数、原消息规则；再安排真实普通Claude读取指定本地输入、写入程序并执行其测试，必须有真实命令事件和实际结果。后续复杂任务比较才具有可比执行条件。不能用测试夹具代替模型实际采用证据。
