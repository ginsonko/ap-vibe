# 在工作室安排伙伴

进入 **Agent 工作室** 后，默认打开工作室。电脑上看地图，手机上默认看名单，也可以随时切换。

## 看进展

- 点击角色或名单，查看当前任务、最近公开事件和更新时间。
- 同一伙伴有多个活动任务时显示数量，可在“查看哪次运行”切换。活动任务不会被较新的已完成记录遮住。
- 点击“过程与成果”，直接打开对应运行的输出与实际文件。
- 用上方的项目、名字、模型或职责筛选伙伴。一个房间最多同时放四个角色；人数更多时，房间标题提供“查看全部”，名单保留所有伙伴。
- 点击右上角展开图标，可在大范围工作室中查看地图和详情。减少动态遵循系统设置，连接中断时保留最后现场并停止动态。

房间是已观察到的工作状态：资料查阅区对应明确的读取工具，工程办公区对应明确的文件写入，验收区对应独立检查或待验收，等候区对应依赖等待和异常，休息区对应已结束运行。普通命令执行无法可靠区分具体工作类型，因此显示在协作办公室。位置不代表工作质量，成果返回也不等于通过验收。

## 安排与交流

1. 选中伙伴，点击“安排工作”，在原有任务表单里选择项目并填写目标。
2. 多人协作进入“任务池”，填写验收标准、候选伙伴、上游依赖和验收伙伴。
3. 想补充要求时，用详情里的“给伙伴留言”。消息立即保存，不需要等动画；回执丢失后重试同一条消息不会重复保存。

也可以把目标直接交给已配置伙伴，让它通过共享 Skill/MCP 读取任务池并登记分工、候选与独立验收。它可以给自己排后续任务，当前回合结束后再执行；任务会出现在同一任务池里。一次真实规划、两个工人、三次独立检查和成果汇总的过程见[自主分工实测](AGENT-COLLABORATION-TOOLS-RESULTS.md)。小任务不必强行拆分，团队开销需要实测。

“已提供”表示消息已经进入公共协作记录，并可供运行读取，不等于伙伴已经理解或执行。正在运行的CLI何时主动读取消息，取决于其工具调用；工作室不会伪造已读。

伙伴换工作区域时会沿房门和走廊移动。新保存的伙伴消息会出现走近、交流气泡和返回的演出，点击气泡可以看原文。旧消息不会在重开页面时重播，密集消息合并显示数量。所有消息在演出前已经保存，动画不控制任务或发送速度。减少动态模式仍能看到状态和消息。

## 了解实测表现

打开“实测表现”，先选时间和任务类型，再点一位伙伴查看实际经历。独立通过率只覆盖有检查项与文件哈希的作者成果；“暂无独立结论”不等于伙伴不能使用。每条经历可进入原运行与实际文件。配置改动后旧版本保留，新版本没有样本时如实显示未知；“各版本样本”可以核对不同模型的历史。

页面还显示已知费用估算和缺失次数，不把缺少金额的Codex任务当成免费。刷新只读取本机记录，不启动模型。职责偏好可以从铅笔图标修改；安排实际工作沿用原任务入口。具体口径、首次单人与团队对照以及局限见[实测表现说明](AGENT-CAPABILITY-RESULTS.md)。

## 换外观

在 **伙伴与配置 → 编辑 → 形象与职责** 选择九套内置外观，也可展开“导入自己的像素形象”：

1. 选择一张透明PNG，最长边不超过2048像素，原始文件不超过2MB。
2. 填写名称。普通单张形象无需准备JSON；有动作图集时才选择配套JSON。
3. 点击“导入并选择”，再保存伙伴配置。

素材保存于当前本机服务的数据目录，重开页面仍在。相同素材重复导入复用同一ID；修改素材或名称会得到新的不可变ID，不覆盖历史外观。从可选外观中移除只隐藏目录项，既有运行引用的图片保留。

图集按行排列，索引从0开始。每帧尺寸必须整除图片尺寸；最少提供idle动作。`frame_width`、`frame_height`、`anchor`和`animations`示例可从导入界面下载。支持idle、walk、work、read、talk、wait、rest及后续扩展动作；缺失动作使用idle。单张PNG只表示静态外观。

内置外观中，DeepSeek、GPT、Gemini、Claude、Kimi、Qwen、GLM、OpenCode和Grok已各提供32帧基础动作，包括四方向行走、工作、阅读、交流、等候和休息；等候与休息共用舒缓站姿循环。选择外观后，可用“预览动作”查看实际播放和缺失项。旧外观在历史记录中保持原版本，已配置伙伴不会被自动换装。地图为本地原创像素位图，生成脚本与出处位于 `tools/draw_office_map.py` 和 `apps/studio/public/office-map.source.json`。详见[动作验收记录](AGENT-CHARACTER-ANIMATION-RESULTS.md)。

想制作自己的形象时，在同一区域点击“请伙伴制作外观”，填写要求，再点击“准备制作任务”。系统会把描述、当前参考图、PNG/JSON规格和验收要求带入任务表单，并选中“使用已安装的媒体工作流”。选择制作伙伴与项目后开始；原来未保存的伙伴配置可用“继续编辑伙伴配置”返回。需要时可以取消媒体工具选项。

媒体扩展使用本机已安装的万能媒体工作流与已配置服务，可能产生API费用；准备任务本身不会发起付费请求。续办或交接会保留原任务选中的扩展。未安装媒体插件时，伙伴会说明缺口并继续可完成的本地工作。已有图集可由伙伴通过 `ap_vibe_appearance_import` 直接导入，再用 `ap_vibe_appearances` 回读；不用把图片编码复制到对话中。真实Claude断线后由Codex完成旧素材恢复的过程见[媒体工具与恢复实测](AGENT-MEDIA-EXTENSION-RESULTS.md)。

## 验证范围

当前已实测：桌面和手机布局，真实历史任务与成果跳转，项目筛选与搜索，长名称，同模型多伙伴，同伙伴多运行，活动记录优先与新异常可见，断联保留、重连，消息丢失回执的幂等恢复，PNG及动作图集导入、非法帧拒绝、刷新保存、归档后历史图片可读、减少动态。

状态变化和消息故障使用独立本地服务的明确标注夹具；历史任务和成果来自之前真实模型验收。新增通道移动、32帧实际切换、沿途改方向、消息先保存后演出、旧消息去重、气泡不遮挡角色、长文本、制作任务准备、系统减少动态均已由浏览器操作验证。真实工作台重启后也读取到消息投影，并可预览新动作，原有配置没有被替换。真实模型导入的自定义图集也已在桌面和手机选择、播放、保存及刷新回读。

普通Codex/Claude跨应用接续、共享工具规划与首次小任务能力对照已有各自实测记录，详见[接续实测](CROSS-SESSION-CONTINUATION-RESULTS.md)、[自主分工实测](AGENT-COLLABORATION-TOOLS-RESULTS.md)及[实测表现](AGENT-CAPABILITY-RESULTS.md)。Grok新图集已由托管伙伴经媒体Skill/MCP实际生成、检查和导入，详见[媒体委托实测](AGENT-MEDIA-EXTENSION-RESULTS.md)。普通工程任务已真实写程序、执行测试并完成一次缺陷返工；复杂工程独立验收又发现输入保护问题，仍在返工，复杂任务净收益和最终安装发布尚待验收。
