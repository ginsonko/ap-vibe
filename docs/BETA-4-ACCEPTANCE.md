# v0.3.1-beta.1：个人内测范围与建议

任务监看、项目档案与记忆、逻辑观察、可选 AP 认知仍是基础；工作室负责可选分工、依赖、交接与验收。此次增加跨系统入口、经济型分工与 WorkBuddy CLI 的有限接入，修复工作室活动区域投影。

## 已验证的增量

- **伙伴简历**：可编辑费用档位、擅长类别、自定义类别和初始印象来源。初始数字是分工偏好，不是公开模型跑分。
- **实际战绩**：同类、配置兼容、可归因的裁决影响排序；有效样本增加时，经验权重按 `n/(n+6)` 平滑提升，强度可修改。同一逻辑任务的重试不重复计票，自报完成和单纯网络故障不作为作品质量。
- **正式数据回读**：已有 Grok 同类记录的经验权重分别为约 7.69% 和 14.29%，排序已经采用这些记录；常规编码推荐经济伙伴，关键攻坚保留高价选择。此为当时配置下的证据，不是固定榜单或净省钱结论。
- **费用记录**：支持标注混合参考价，价格变更只影响后续请求；旧记录和未知费用保留。用户可设置或不设置预算。参考价不等于账户余额，不承诺各执行端都具备逐请求预算拦截。
- **工作室区域**：真实阅读、编辑、测试动作投影到相应区域；后续网络状态消息不会覆盖刚发生的实际动作。验收任务读资料时也能去资料区。普通 Codex/Claude 的工具动作同样参与归类，未知动作不随机移动。
- **界面**：正式浏览器打开 WorkBuddy 的四条真实会话及模型、伙伴简历、已保存的混合参考价，并切换各主页面与窄屏阅读，无 JavaScript 异常。管理历史默认折叠，伙伴配置入口更靠前。
- **系统**：Windows 全量合同测试；macOS、Ubuntu CI 真实启动服务并检查端口回退、重复启动、停止、持久保存与加密路径。适配器缺失只收缩对应能力。

## WorkBuddy 的准确边界

Windows 本机已登录的 WorkBuddy 5.5.6 内置 CodeBuddy CLI 2.137.1：真实短请求返回成功，实际模型 `glm-5.3`；另一次 `glm-5.1` 读取已装 Skill，通过本地工具桥实际查询 AP-Vibe 项目目录。公开会话中的标题、文本与实际模型可在工作台读取。

原生 MCP 虽报告已连接，模型两次均未执行真实 MCP 工具调用。因此本版使用 Skill 工具桥，**不宣称 WorkBuddy 原生 MCP、GUI 会话历史、GUI 唤醒或工作室托管已通过**。工具桥测试中保留原生权限拒绝与路径修正记录；普通用户仍使用原客户端的工具审批，不要求关闭其保护。未在 macOS/Linux 的 WorkBuddy 客户端上做真实登录任务验收。

## 推荐给内测用户的第一轮体验

1. 把 README 中的安装口令交给 Codex，先用自己的一个小型长期项目。确认工作台打开，原有项目和配置仍在。
2. 在熟悉的客户端完成一项小修改，再换另一个已接入客户端；让它通过 AP-Vibe 读取项目资料和上个任务的公开进度，接着做另一项修改。检查旧决定与待办保留。
3. 有复杂、可拆分工作时开启协作。只给已安装执行器下的伙伴配置连接，查看管理员的分工依据、真正的成果和最终验收；不要用普通一句话问答测试多模型并行收益。
4. 查看工程区、资料区和故事回放；角色位置是公开动作的表现，不代表模型内部思考。配置简历后观察一段时间的同类战绩，再调整偏好。

## 仍需持续内测

各模型的稳定性、质量和综合费用需要更多同类实际任务。初始偏好可修改，未知模型可正常参与合适的小任务；没有固定智力排名，也没有全自动零错误保证。

CI 不是所有操作系统发行版、实体设备、网络环境和第三方客户端版本的全面验收。POSIX 暂不提供 Windows 桌面快捷方式，也不自动切换正在使用的更新候选。普通外部终端的收件箱读取与任意窗口即时唤醒不同。跨系统搬迁需要重新配置无法互解的 Key。

反馈请提供版本、系统、客户端、原目标、操作步骤、实际结果和脱敏截图。不要发送 Key、Cookie、原始完整会话或数据库。宣传图片和视频另行审核，本版沿用文字说明与实测范围。
