# 普通 Codex 与 Claude 接续实测

2026-09-10，普通全局安装场景已完成一次 Codex -> Claude -> 原 Codex 的真实往返。测试工作目录在仓库之外，使用真实模型、原生 CLI、默认会话记录位置和全局 Skill/MCP；未使用工作室托管运行器，也没有给第二个会话复制对话或准备交接文档。

## 实际过程

1. 普通 Codex 只编写库存 CSV 的读取器，实际检查五个数值字段转为整数，然后按要求停止。业务规则和剩余工作留在它的公开对话里。
2. 普通 Claude 只收到“刚才这个目录的 Codex 任务做到一半，现在换到这里继续”。它自行加载 AP-Vibe Skill，查询当前目录的会话，调用公开消息读取工具找回原规则，检查两个工作文件后续做。
3. Claude 写出补货逻辑和 JSON。独立回读确认结果 A=18、C=12、D=10，B/E 排除，原 CSV SHA 不变；再次调用它写出的函数也得到相同结果。边界样本覆盖阈值相等、负库存、包装向上取整、停售排除。
4. 原 Codex 普通会话恢复后，通过客户端会话目录和精确读取入口找到了 Claude 的最新结果，再独立重算并核对真实文件。它没有重新实现或建立一次性项目档案。
5. 浏览器实际打开这条 Claude 会话，桌面 1440 和手机 390 宽度都能按标题查看、在有界消息区读最新输出；消息区 418px，实际无横向溢出或页面错误。
6. 核对没有活动托管任务或整理任务后，用正式生命周期脚本停止并重新启动服务。再次读取相同会话来源、原文件与结果，独立重算和原 Codex 反向读取证据仍通过。此项证明服务重启恢复，不等于 Windows 整机断电验收。

证据保存在本机私有 `.local-acceptance/ordinary-continuation-v2/`：`receipt.json`、`acceptance.json`、`browser.json` 和两张截图。公开仓库不包含真实会话、连接配置或运行日志。

## 实测发现并修复的问题

- **默认 Claude 找不到 MCP**：原安装器给默认目录设置了 CLAUDE_CONFIG_DIR，注册到了另一个配置文件。现在区分原生 `~/.claude.json` 与显式目录的 `.claude.json`，注册后回读，保留其他设置。新普通 Claude 实际报告 ap-vibe connected，并实际使用新工具。
- **缓存不可写被误报为读取失败**：Codex 的受限执行环境可读本地服务，却不能写全局收据缓存。客户端现在保留在线返回的真实收据；缓存失败只影响下次缓存命中，直接读取和按收据查询仍可用。负例已覆盖 bootstrap 和 knowledge。
- **“最新”不等于采集窗口前 32 条**：统一读取接口单独提供最新一页、历史页和新增游标，复用原公开内容解析器，不推进认知采集游标。半行、轮换、坏 JSON、多块消息和响应大小均有定向检查。
- **本机路径被导出脱敏遮掉**：本机接续接口保留成果位置，同时脱敏凭据；原 portable 导出继续隐藏本机路径。

首组验收另有两条真实失败记录：用户 Claude 的旧 settings.env 连接覆盖了环境变量，首次请求得到 401；下一次缺 MCP 时，模型绕读到了验收脚本的预期答案。这两个样本均未记为成功，第二个已停止。修复后移到独立工作目录，最终 Claude 的文件读取仅涉及 Skill 接续说明与工作文件，来源恢复由真实 MCP 完成。
