# 自动验收、返工与成果阅读

你可以让一个伙伴完成任务，再让另一位伙伴按完成标准检查。发现问题后，AP-Vibe 会把原成果和具体修改意见交回作者；作者在新目录修正后，检查伙伴再次核对。每一轮的文件、意见和结果都能回看。

## 从哪里开始

1. 打开“Agent 工作室 → 任务池 → 新建任务”。
2. 选择项目，填写“要达成什么”和“怎样算完成”。例如：“写一份安装教程”；完成标准：“说明安装步骤、本地模式、可选联网功能的费用，并给一个新手例子”。
3. 选择执行伙伴和验收伙伴，开启自动领取。自动返工默认两次，检查连接失败后默认恢复一次，均可调整；零表示关闭对应自动动作。
4. 保存后查看任务详情。这里会显示当前进度、逐项结论、修改要求、返工次数，以及“打开完整报告”。

同一个伙伴不会同时担任这项任务的作者与独立检查者。可以使用相同模型创建两个伙伴，但不同会话不保证模型判断没有共同盲点。

## 结果怎样流转

| 实际结果 | AP-Vibe 的处理 |
| --- | --- |
| 作者返回成果 | 显示“成果待验收”，自动启动检查伙伴 |
| 所有检查有证据且通过 | 保存裁决，任务完成，依赖它的普通后续任务可以启动 |
| 检查发现具体错误 | 保留报告，自动返工预算尚有剩余时交给原作者修订，再次检查 |
| 缺少判断依据 | 显示“暂时无法判断”，保存证据缺口 |
| 检查失败且没有提交结论 | 实际进程已经退出时，按恢复次数创建新的检查请求，重新读取同一版作者成果 |
| 已保存结论，末尾回复断线 | 实际进程退出后重新核对报告、原文件和任务归属，恢复结论；无需再次调用模型 |
| 报告/原文件变化，或用户已另作决定 | 保留旧结论及具体原因，不覆盖新决定 |
| 自动次数耗尽 | 保留全部成果与错误，用户可继续分配 |

报告通常为 `acceptance.md`。运行详情的“成果文件”支持 Markdown、表格、代码和文本；大文件标明预览范围，连接断开时保留已读内容。旧作者文件、历次报告和请求记录不会被返工覆盖。输出目录隔离不是操作系统沙箱。

## 真实验收证据

2026-09-09，两个使用 `grok-4.6` 的独立托管伙伴完成了一次完整教程返工。初稿故意写入“AP 认知永久免费且不用联网”和“返回文字就已验收通过”两条错误。检查伙伴读取文件，引用原句并提交“需要修改”。作者自动在新目录修正，补上本地基础模式、可选教师的联网和 API 费用、长期收益未知、成果待验收与通过的区别，以及新手操作例子。

第二次检查遇到了上游连接异常，进程退出后，系统自动创建新的检查尝试。新的检查伙伴读取同一版修订稿和原检查意见，逐项给出依据并提交“通过”。整个过程包含一次返工、两个逻辑检查任务、五次模型运行。原始错误草稿仍保留，服务重启后结果与文件版本仍一致。

五次运行的 CLI 费用估算合计 **3.953245 美元**。这不是供应商结算账单，也不证明此流程比单个伙伴更便宜或更快。这个案例证明的是自动检查、具体返工、异常恢复与结果回读可以协同工作。

本地测试另覆盖：同一裁决并发提交、重复调度、事务中途失败、报告/原文件被修改、旧任务归属、用户另作裁决、取消、进程未退出、返工与恢复次数为零，以及保存裁决后的末尾断线。最后一种使用隔离故障注入，不冒充另一次真实上游故障。

真实浏览器已验证任务详情、历次结论、Markdown 报告、不同运行切换、桌面与手机宽度，以及关闭自动执行时新建/归档不调用模型。这些证据覆盖上述路径；全站全部按钮、干净安装、多模型长期质量和复杂任务效率对照仍需完成。
