# 通用协作示例：按批次检查图片

这是从 Codex / Claude Code 自然任务使用工作室工具的一个例子。v0.2.0-beta.1 没有独立的“批量图片验收”页面；无需寻找专用卡片或学习工具参数。

个人内测请使用个人非经营素材、合成样本或已获授权的非生产图片。企业、客户或电商正式经营用途需要另行书面授权，详见仓库 LICENSE。

## 把这段需求交给当前任务

> 请检查这个图片目录，对照参考图和我的标准，找出错色、错字、变形、裁切等问题。通过 AP-Vibe 选择已配置且实际支持图片输入的伙伴，先校准一小批代表样本。标准和模型效果明确后，再分批处理其余图片；保留原图、逐图结论、理由和未知结果，不要在主会话里逐张加载全部原图。最后给我可读取的结果清单和需要人工复核的图片。

提供本机可访问的文件夹完整路径和具体标准；参考图可选。先确认任务是否允许把图片发送给所选服务商。不要把 Key 写入需求、公开记录或图片文件名。

## 正常的处理过程

1. 开启自动协作，或明确授权这次委托；查看伙伴是否有完整连接。模型名出现在列表不等于该渠道已支持图片。
2. Agent 先读验收标准，挑选覆盖正常与缺陷的少量样本；通过批次工具验证图片读取与判断能力。一次任务不能靠同一个模型自评证明准确率。
3. 校准符合预期后，按批次扩展。主任务处理标准、异常和汇总，合适的视觉伙伴处理重复判断，不为每张图启动一个完整编程会话。
4. 在工作室查看真实运行和输出；需要时直接对原任务说“暂停新增检查”“从保存进度继续”“导出逐图清单”。Agent 使用同一批次工具，不另建重复任务。
5. 读取成果，抽查原图、误拒和漏检；拿不准的保留复核，未知请求先对账。数量完成不代表所有质量判断正确。

暂停仅阻止新的提交，已在途请求仍可能完成和收费。继续处理尚未提交的部分；状态未知的请求先核对原记录，不盲目重发。角色动画与“已执行”不等于独立验收通过。

## 费用与证据

模型请求可能收费；本地金额显示“0，未估算”表示没有价格信息，不是免费。建议供应商侧设置 Key 额度。费用比较要包括校准、检查、复核、返工和缓存口径，不能只看单次模型价格。

早期一组8张受控图片的真实 Grok 渠道结论与该组预置真值一致；另有4000项隔离队列恢复测试。前者只覆盖这个小样，后者只覆盖队列逻辑，都不证明4000张客户生产图片的准确率、速度或账单。Gemini 渠道也曾返回503，失败记录保留。

首次试用从小样开始，优先检查用户是否少了手工搬运、结论是否能追溯、未知项是否被保留。更多任务类型沿用同一套自然委托、依赖、成果与独立检查能力，无需给每种业务增加页面。
