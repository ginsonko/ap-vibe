# 项目档案迁移：实际操作与验收

现在可以从“项目与记忆”导出项目，在另一套工作台通过“导入项目”创建独立副本。导出内容包含当前11章档案、十维分析、最近有界历史摘要和已有本地恢复资料。原始代码、密钥、完整会话、所有历史版本和运行中的任务仍需分别迁移。

2026-09-10，使用真实普通 Codex 任务自行创建的设备借用登记档案，在独立数据目录和端口完成以下流程。主任务没有手填或修改演练档案。

| 步骤 | 实际结果 |
| --- | --- |
| 点击原工作台“导出当前项目” | 下载包含11章和十维分析的JSON |
| 打开另一套工作台，选择损坏JSON | 原地说明文件无效，没有发起导入 |
| 选择有效文件，填写本机项目目录 | 显示文件名和副本名称，可直接预览 |
| 查看预览 | 显示11/11章、10/10项文字分析、来源第1版；预览未创建项目 |
| 桌面与390像素手机查看 | 表单和数字无横向溢出，操作可通过滚动完成 |
| 确认后丢弃浏览器响应 | 服务已经保存；页面保留同一确认请求 |
| 刷新页面并重试 | 返回同一个项目，只有一份第1版档案 |
| 打开导入项目 | 副本名称正确，11章逐项相同，原评分未知，来源版本明确 |
| 重启独立服务 | 再次读取11章一致，5条导入历史摘要可展开阅读 |
| 再次导出 | 当前档案与脱敏后的历史摘要继续保留 |

真实测试发现并修复三处问题：冷启动时目录返回导致导入表单关闭；浏览器重新序列化JSON把1.0变成1，造成内容校验失败；旧导出只脱敏嵌套活动，遗漏外层摘要里的本机路径。现在表单保持、上传下载使用原始文本、完整导出包统一脱敏，仍保持内容校验。

针对性检查还覆盖：缺档案旧包、无效档案/评分、重复预览、阶段提交后中断、人工修改后重启继续、浮点与大整数、外层摘要脱敏。原始失败记录保留，未用放宽hash检查或删除旧数据来绕过问题。

这是同一台电脑上两套独立数据目录的迁移演练，尚不等同于另一台实体电脑或另一操作系统的验收。导入资料保留来源和原结论，不因此成为本机新验证的事实；历史学习快照不自动激活为运行规则。包大小目前限制为2MB，代码与完整审计备份不应使用这个有界资料包代替。
