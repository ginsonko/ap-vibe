# v0.4.0-beta.2：更新器限流恢复修订

本修订承接 v0.4.0-beta.1 的 Grok Desktop / CLI 原生接入，修复未认证 GitHub Releases API 达到 60/60 后更新检查直接停在 `check_failed` 的问题。

## 更新行为

- 使用 GitHub Releases API 时保存 ETag；收到 403/429 会记录原始状态、`Retry-After` / `X-RateLimit-Reset` 和下一次检查时间，不在冷却窗口反复请求。
- API 不可用时读取公开版本标记，再从同一标签的公开 Release 地址获取清单和应用包。版本标记只用于发现，不能绕过 manifest、存储合同、压缩包 SHA-256、路径和逐文件校验。
- “仅正式版”不会回退到 Beta；未发布标签、旧版本和损坏包不会被报告为可安装或当前版本。
- 已经通过校验的同版本暂存包可以复用，避免重复下载；安装仍等待现有任务空闲，并保留旧配置、项目档案、数据库、Key 位置、Grok home 和其它规则。
- 工作台会显示失败阶段、备用查询来源和下次重试时间。固定标签链接可在旧版更新器上手动恢复，不需要 GitHub Token。

## 验证边界

- 公开包、清单、raw 版本文件和修订版本地测试已验证；真实 GitHub 共享出口的 403/429 只做受控模拟，不主动耗尽公共配额。
- 本机全量 Python 回归：801 passed、5 skipped；前端 production build 和 Node tests：35 passed。
- 真实 `v0.4.0-beta.1` 包通过 443 文件校验；修订版新增逻辑在隔离配置中通过 API 403 回退、429 回退、ETag 304、stable 防误装、旧版本防降级、损坏包阻断、配置不变和暂存复用测试。
- 这是个人非商用 Beta 修订。用户网络对 GitHub Release 文件的连接重置仍需按域名和实际 HTTP 步骤单独排查，不与 API 限流混为一谈。

- Windows 隔离首次安装、重复安装单实例和从 v0.4.0-beta.1 无损升级通过；保留数据库历史、自定义配置与两个 Grok home，安装集成问题为空。
- 补充压缩包哈希格式检查后，更新/打包定向测试 28 项通过；最终提交的全量结果以 GitHub CI 为准。
