# 跨应用继续同一个项目

AP-Vibe 的四项基础能力仍是任务监看、项目档案与记忆、逻辑观察、可选 AP 认知。跨应用接入让这些资料可以被更多编程客户端使用；Agent 工作室继续负责可选的分工、依赖和成果交接。

## 第一次怎么用

1. 照常使用已安装的客户端。打开 AP-Vibe 的“会话”，默认查看全部应用，也可以按应用筛选。点一条会话读取公开消息；标题、模型和来源按客户端实际记录显示。
2. 在“项目与记忆”整理长期项目。不同应用维护同一套代码，应共用一个项目档案。新会话先查询档案和近期公开输出，修改后增量更新，保留旧决定、事故、备注和待办。
3. 想分工时，再开启协作并在“伙伴与配置”选择已安装的执行端、填写模型连接。支持的工作室执行端可以创建任务、恢复原会话、读取工作留言并交接成果。普通客户端是否能即时唤醒，取决于它提供的接口。

可以把这句话交给另一个已接入的客户端：

> 请通过 AP-Vibe 查找这个代码目录对应的项目，阅读当前进度、决定和恢复入口，再读取上个应用的近期公开输出。核对真实文件后继续剩余工作；结束前增量维护同一份档案，保留旧事故和待办。

## 会话没出现时

在“会话 → 管理会话来源”查看发现状态。便携版、定制数据位置可以填写绝对目录；多个目录每行一个。保存后刷新，也可以恢复自动目录或关闭单个来源。

常见入口：Hermes 是包含 `state.db` 的目录；DSH 是 `DSH_HOME/sessions`；PI Desktop 是其数据目录中的 `sessions`；GenericAgent Admin 是实际 `chat_data_dir/chat_sessions`。使用运行配置确认路径，不能按窗口标题猜目录。这里只修改 AP-Vibe 的监看设置，不搬动或改写第三方原始会话。

DSH 压缩会话需要 `zstandard`。安装器会尝试补齐；离线缺失时明确提示此来源缺依赖，其它应用继续可用。未知格式、正在追加的不完整尾部和损坏记录局部降级，不把旧格式冒充最新会话。

WorkBuddy 的内置 CodeBuddy CLI 使用 `~/.codebuddy/projects`（可在来源管理中改目录）。
它与 `~/.workbuddy/workbuddy.db` 的 GUI 会话不是同一来源。在会话筛选中选择
“WorkBuddy / CodeBuddy CLI”。当前接入安装到 CLI 的 `.codebuddy/skills`，
不修改桌面登录、连接器密钥或原生权限。CLI 查询走与其它应用相同的本地工具 API；
原客户端要求审批时仍使用其正常审批。一次短任务成功不保证每个模型都自然触发 Skill，
也不代表零成本；原生返回的 `total_cost_usd=0` 不能代替供应商账单。

## 安装与接续边界

安装或更新 AP-Vibe 时，为发现的兼容客户端同步接入。现有模型、Key、权限、其他 MCP 和人工修改应保留；遇到无法安全合并的 JSONC/YAML 配置，保留原文件并返回准确配置片段。便携目录可按安装器帮助指定。

没有 MCP 的客户端可以使用 `tools/native_client.py` 调用同一套工具。安装后的 Skill 用 `references/installation.json` 定位 Python、当前工作台配置和产品目录；不要复制另一台机器的绝对路径。所有身份使用实际应用和真实会话 ID，运行 Grok 的 OpenCode 仍属于 OpenCode。

普通第三方终端的返回消息会保存到 AP-Vibe 收件箱，下次 Skill / 工具调用读取。本版不会为了“即时唤醒”而启动同一会话的第二个写入进程。托管会话的恢复和普通窗口远程控制是不同能力。

原生执行端的用量、预算阻断和重试机制不完全相同。能从公开事件读取的用量会记录；供应商账单才是实际计费依据。新增执行端没有 Claude 网关逐请求预算拦截的完整等价性，建议同时配置供应商 Key 额度。没有价格或没有完整用量不表示免费。

## 已完成的跨应用档案验收

同一持续运行的隔离工作台内，OpenCode 创建“离线设备维护日志”样例项目，MiMo 在同一目录增加设备筛选。独立回读确认：复用同一项目 ID，两个真实应用会话分别登记归属，档案从第 1 版增量更新为第 2 版；11 章和十维说明齐全，其中两项缺证据的分数为空。旧决定、UTF-8 事故、用户原始停机备注和未实现的 CSV 导出待办保持；实际程序筛选通过。工作台进程重启后再次回读，当前版本和历史版本内容哈希保持一致。

第一次 OpenCode 尝试没有真正建档，沿原会话指出真实错误后才完成；此失败记录保留。因此本次证明了实际链路和接续能力，没有证明所有模型都能在首次任务中自然完成，也不保证每个任务更快或更省。PI Desktop 的 Skill/MCP 与 DSH 的 Skill 回退另有真实调用和成果文件核验。

个人内测优先验证自己的两个客户端能否继续同一项目。反馈请附版本、应用、目标、失败步骤和脱敏截图，不上传 Key、完整原始会话或数据库。
