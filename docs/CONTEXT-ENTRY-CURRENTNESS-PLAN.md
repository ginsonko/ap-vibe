# 按需恢复入口与当前资料

目标：普通任务启动时准确知道项目是什么、最新档案版本和各章入口，避免历史里程碑或无关观察抢占上下文。保留所有历史资料及归因能力，不修改 AP 认知存储或项目归属。

现场发现：bootstrap 每次先拼旧 reviewed brief，再按词项交集排序六条观察；交集为零也会填满六条。hook 再自动复制旧摘要和三条观察。即使最新档案已经更新，新任务仍可能看到相反的旧待办。

设计：默认返回当前档案目录、版本、逐章摘要，以及最多三条与明确目标有词项交集的观察摘要；缺相关项就留空，不自动填充。不将观察正文或旧里程碑正文塞入默认入口。需要历史时显式 include_history 读取，历史入口和独立版本始终可见。hook 只携带当前目录与简短读取/收尾说明，实际服务链接由客户端提供；新手三步引导仅适用于初次接触，不要求每轮都打开固定端口。

实现范围：task_context、MCP输入说明、CLI选项与Skill文字。旧receipt按原内容重放，不能修改已经交付的事实或归因；新请求才使用新投影。没有身份、没有项目、服务离线均保持原可用回退，不增加读取门槛。

对抗审查：资料摘要仍是不可信参考，不提升级别；agent_reported不能说成已审。检索词项只是简单排序，不声称AP自主认知，零匹配不等于无可用历史。请求中include_history必须进入幂等指纹，防止同request_id不同内容。检查旧版本回放、跨项目隔离、归档观察、秘密脱敏、当前档案优先、默认返回不含旧待办、历史显式可读，以及真实服务/MCP和hook回读。随后完成一次真实普通长期任务的资料接续与增量维护，独立核对文件和版本；不重复旧模型实验。

实测追加：原生CLI指出Stop事件不支持additionalContextLimit。只从AP-Vibe自身Stop配置中移除这个无效字段，保留启动事件和其他用户hook；用安装输出及真实CLI不再出现该警告验证。普通CLI第一次运行遇远程插件/连接器连续超时，保留失败和部分读取；新恢复请求沿用原session，仅在该进程关闭无关远程扩展，不改用户全局偏好，不重放原请求。
