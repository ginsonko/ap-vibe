# 制作伙伴的媒体工具与恢复实测

2026-09-10。本阶段已验证：托管任务带入本机已安装的媒体 Skill/MCP，读取原媒体任务，用本地工具检查 PNG，并将图集导入工作室；Claude 中途断开后，Codex 在复制后的成果目录完成剩余文件。随后一次新的Grok形象委托实际完成两张新源图生成、切图、视觉检查、32帧合成和MCP导入。旧素材恢复与新素材生产分别保留证据。

## 对用户的变化

- “请伙伴制作外观”会准备参考、规格和要求，并默认选中“使用已安装的媒体工作流”。填写任务后可取消这一选项，准备过程不调用模型。
- 选中的扩展跟随续办、交接和任务池记录，避免换伙伴后工具消失。缺少媒体插件时明确说明缺口，已有项目资料与本地工作仍可继续。
- `get_session` 默认返回任务身份、节点与成果目录。指定 `node_keys` 才展开所需节点；完整原响应以哈希保存，失败和未知状态保留。
- 伙伴使用 `ap_vibe_appearances` 查询外观，使用 `ap_vibe_appearance_import` 导入本地 PNG/JSON，再回读 ID。图片字节不进入模型参数，用户不必复制 base64。
- 旧任务未关联当前工作的消息保留在历史目录，不再自动混入同一伙伴后续的所有任务。关联逻辑任务或明确交接来源的消息仍随工作提供。

## 实际发现与修复

首个 Grok 媒体任务成功读取 Skill、检查 32 帧并导入外观，但报告夹带了上一项销售任务的规则。原因是无任务关联的旧广播被自动注入新工作。原报告保留并记录为需要修改；新的任务上下文按工作关联选择消息。

原媒体任务历史较长，首次返回约 145 KB。紧凑目录约 16 KB，同时保存完整原响应的文件与 SHA-256。它减少默认工具输出，不证明模型费用同比下降，也不会删掉失败生成或重新提交原请求。

第二个 Claude 尝试使用紧凑目录和 Pillow 后发生上游断开。原目录已有图集和探针，缺少可导入 JSON 与最终报告。真实 Codex 交接继承媒体扩展，查到同一媒体任务、节点与外观，补齐三份文件并回读；原 Claude 尝试继续保留 `uncertain`。

## 新素材委托实测

同一个持久媒体任务中，托管Codex读取实际节点目录和最新计划，提交Grok行走与办公动作两张图片，只查询本次已受理请求直至结果返回。它查看实际源图，按透明间隔调整切分边界，产出384×768的32帧图集、JSON清单、联系表和验收报告，通过MCP导入并回读相同外观ID。主任务再次查看源图和联系表、核对SHA，并通过真实浏览器检查桌面/手机动作播放、保存、刷新、减少动态效果和办公室显示。

本次两张新图的模型目录估价共1.6元，实际供应商账单未知；这不是统一报价。原失败生成、先前账务未知请求和交接历史均保留，没有将它们改成成功或重放请求。原九位伙伴配置未改变，用户可以按需要选择新外观。

九套角色现在均有基础32帧。等候和休息共用站姿，阅读不保证翻页；Grok侧面步态部分帧相似、手部动作较细微，仍可继续美术优化。一次委托通过不保证任意模型、任意素材和任意上游都能一次成功。复杂任务净收益、干净安装与最终发布继续验收。

本机详细证据位于 `.local-acceptance/media-extension-handoff-20260910-v3-acceptance.json`、`.local-acceptance/browser-media-appearance.json` 和 `.local-acceptance/media-proxy-acceptance.json`。这些含本机运行位置的验收收据不随公开仓库发布。

新委托证据另见 `.local-acceptance/grok-media-commission-acceptance.json`、`.local-acceptance/grok-media-commission-qa-result.json`、`.local-acceptance/grok-media-commission-browser.json` 和 `.local-acceptance/browser-grok-actions.json`。
