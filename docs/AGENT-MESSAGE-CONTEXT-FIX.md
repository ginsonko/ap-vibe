# 无关工作消息混入新任务

真实媒体恢复验收发现：Grok在处理PNG时引用了上一项销售核对的paid/order_id规则，甚至写入最终acceptance.md。来源已定位为两小时前未绑定task_id的协作广播，for_task仅按recipient把它自动注入同一伙伴的每个新运行。

这不是权限问题：全部历史消息仍应可以查询。但读取目录与自动作为当前工作上下文是不同操作。启动上下文只选当前run、逻辑task、明确接续/交接源运行，以及直接以这些run为收件人的消息；同一任务仍按收件人选择。无任务绑定的旧信继续留在协作目录，不再跨任务自动注入。

使用已有task_id即可为尚未启动的逻辑任务发消息，等待和返工会继续取到。共享Skill补充这一用法；不增加用户确认、不删除历史、不按模型设置门控。运行提示提醒消息是带来源的参考，不能扩大当前目标。

审查：防止同伙伴多任务串线、同逻辑任务不同收件人混入、续办/交接丢失原消息、旧消息被删除。以定向回归和新的真实媒体核验任务确认。首个媒体任务技术文件通过但报告含无关规则，保留缺陷，不把它登记为完整质量通过。
