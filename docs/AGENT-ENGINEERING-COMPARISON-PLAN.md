# 实际资源检查工具：单人与团队对照

## 目标与输入

现有八行销售样本显示小任务拆分成本偏高，不重复该实验。普通Claude执行器现在已实际运行程序，并通过缺陷返工和独立验收。本次用实际角色资源制作可独立使用的发布检查工具，覆盖多文件遍历、路径边界、PNG与动作合同、稳定报告和命令行错误行为。先冻结四套已验收图集的副本与SHA，单人与团队读取同一个输入和同一份合同；所有成果写入各自目录，不改原资源。

## 分工与可比较范围

单人由已经完成普通工程验收的Grok伙伴交付全部三个模块和测试；团队由两个相同模型的Grok伙伴分别完成资源发现和单图检查，再由首位Grok整合CLI。Codex本机伙伴独立检查各项真实源码和执行结果，使用系统已有自动验收/返工机制。两个分支在各自原成果上验证同一份独立行为用例。

公共合同及任务说明由本主任务编写，准备成本属于两者共同前置成本。计时从每个分支任务提交到最终裁决，记录排队时间、真实运行次数、实际执行时间、返工与已知CLI估价，并保留未知费用。测试期间运行顺序和上游负载不受控制，单次结果只能作为本场景观察，不推导模型智力排名或普遍提速。不为追求胜出而删去团队的通信、检查或整合开销。

## 功能合同

- `inventory.py`：`discover(root) -> dict`，返回相对POSIX路径排序的`manifests`和结构化`errors`，不跟随链接目录或越界链接，不因一个坏目录放弃其它可读项。
- `atlas_check.py`：`inspect_atlas(manifest_path, root) -> dict`，支持单角色或多角色目录清单，每条记录含id、源manifest、源atlas、SHA、帧数、透明/半透明/不透明数量、各动作与错误。只允许root内实际PNG；检查重复id、无idle/空frames/bool或越界索引、非法帧大小、大小不可整除、hash不匹配。多条记录不能只检查第一条。未知扩展字段保留兼容，不因名字不在模型列表而失败。
- `catalog_audit.py --root DIR --json FILE --markdown FILE`：组合前两模块，输出确定性排序的JSON及中文摘要；返回0表示检查无错，1表示输入质量缺陷且报告已写，2表示参数/输出路径错误；输出不覆盖任一输入文件（包括链接别名），不调用网络，不改变输入；报告不包含绝对路径或凭据。不以文件名推断模型能力，不因缺少非必需动作判定已知静帧不合法。
- `python -m unittest discover`：实际执行可复现测试，附中文README、真实运行命令和结果，不能只给预期输出。

## 对抗性审查

1. 两位作者不能互读单人或其它分支答案；团队整合仅读取系统依赖中的本分支成果；验收读取原文件执行，不信“通过”自述。
2. 多角色manifest、损坏PNG、空/非法JSON、unicode路径、嵌套目录、缺文件、../越界、symlink、输出别名覆盖都属于真实导入可能遇到的情况。Windows链接权限不足时保留未验信息并由主任务独立补查，不捏造通过。
3. 程序合同不能用测试代码中的已知四个家族名单硬编码。以可解析结构与实际输入判断；SHA从字节计算。增加用户素材不需要源码修改。
4. 发现收益为负就如实记录，并用于推荐“小任务单人，真正独立且工作量足够才并行”。不靠无限追加实验寻找想要的结论。
5. 成果技术通过后才考虑纳入发布工具；本实验不自动合并模型产生的代码，也不代表全部产品或安装验收通过。

审查结论：接口边界、输入保护和独立检查已明确，先单人交付再运行团队分支，记录真实故障并走已有恢复路径。无需新建执行器或更换凭据。
