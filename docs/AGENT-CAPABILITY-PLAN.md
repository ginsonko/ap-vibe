# 伙伴实测能力与可比效率

## 目标与事实入口

工作室的配置职责是用户偏好，当前实测能力为null。已有持久studio_runs、逻辑任务tags、逐次验收review_history、结构化裁决和执行器result，可以形成可回溯的观察，不另建评分真相或调用模型来猜分。用户需要按实际经验分配任务、查看成本和纠正偏好，未知模型同样可以使用。

## 实施

1. 新增只读能力投影，从运行和任务记录读取。按伙伴、配置版本、任务标签、时间范围筛选；全表查询保持窗口上限并显示覆盖，不沿用最近80条运行UI的隐含限制。每个run只计一次，保留失败/不确定/取消/待验的不同含义。
2. 区分具实际文件哈希及检查项的独立裁决、人工/其他检查记录、作者自评、检查报告被应用。检查报告应用不等于检查者能力已被独立验证。展示独立通过/需修改、返工、已验样本与未知；不从模型名编排名，不将不同任务的平均耗时当横向智力比较。
3. 费用用CLI原始total_cost_usd，只求已知部分之和，明确样本覆盖和估算来源；null/负数/非有限数都未知。耗时用真实执行器duration_ms或新记录的开始/结束时间，不能把等待人工验收的updated_at当执行时长。Codex无金额不按零计。保留全部运行成本，包括规划、验收与失败。
4. 新任务运行冻结任务标题、tags和验收描述的元数据；旧运行仅可从任务当前元数据解释并标记来源。配置revision改变后旧样本仍可看，但不能伪称当前配置已测。MCP伙伴目录返回小摘要，按需能力工具读取分页证据。任务调度继续尊重用户候选顺序，规划者用实测证据作选择，无额外使用门槛。
5. 中文工作室增加“实测表现”视图，时间/标签/配置/伙伴筛选，汇总与对照表、具体运行与验收理由、未知费用提示；刷新不启动模型，直接跳到原运行和真实成果。允许从此编辑既有职责，开始真实任务沿已有入口。已有运行超过80条也须精确打开。
6. 实际浏览器验证筛选/刷新/证据跳转/配置编辑入口/移动端；用原真实协作记录核对投影，不能插入夹具到正式库。随后选择一个已验任务作真实单Agent对照，质量标准保持一致，统计规划、通信、独立验收及全部已知费用。结论局限于该任务，不保证团队必然快或便宜。

## 对抗性审查

- 返工两次不能计作两个独立成功项目；同时展示运行样本和不同逻辑任务数。一次检查多次覆盖只取最后有效结论，保留历史需修改次数。
- 结构化裁决的source_run_id必须匹配作者；检查者自身“报告已应用”不能获得独立成功样本。没有来源哈希/逐项通过时不混入独立通过率。
- 只显示观察值，无合成100分智商；未知和零分分开。相同模型多个伙伴、不同URL和不同配置版本不混淆。
- 不把网络失败算质量拒绝，不把外部检索权限等宿主边界隐藏。失败可展示供诊断，但不是永久禁用。
- 自动数据回读无LLM费用。UI断线保留上一份、说明数据时间；筛选切换不能沿用上一个范围冒充新数据。完整历史加载可能有上限，必须可见。
- 不新建并行认知层，不更改AP认知权威或旧项目归属，不恢复或重放原付费请求。保留用户编辑/旧配置/历史任务。

审查结论：复用持久记录实施。服务、MCP和前端共用同一投影口径，能力数据对所有已接入会话开放。实际证据不足不阻止模型工作，交付前用真实记录与独立浏览器逐项检查。
