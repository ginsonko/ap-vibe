# 跨工具项目归类与完整档案

2026-09-08。目标是让普通 Claude 长期任务自己查找、选择或创建真实项目，随后按共享协议维护档案。一次性问题不创建项目。现有 Codex 历史整理保持原流程。

## 合同与实施顺序

1. 复用项目注册表、11章/十维校验和不可变文档版本。增加按 client_kind + session_id 区分的会话归属及不可变变更收据。不同工具恰好使用相同会话ID不得相互影响。
2. 增加两个 MCP 工具：projects 分页列已注册项目或按需读候选章节；classify 依据真实来源附加到已有项目，或提交完整11章新建项目。附加不改旧档案。新建、档案、归属、幂等收据同事务保存。
3. bootstrap 返回归属版本；分类用预期版本避免并发覆盖，成功后重新获取上下文。旧收据继续可读，归属变化后不能误写原项目。未分类仍能读候选资料；不凭标题或目录相似强行合并。
4. 普通 Claude hook 和 MCP 明确标记来源。托管任务保留用户选定项目，不因成果目录而变更归属。安装器升级自身 MCP 配置时保存旧配置，不覆盖别人同名服务。
5. Skill 先查目录、查真实证据，再归类；新建时先保存完整请求；异常保留请求，不重放未知的新请求。更新遵守旧字段/人工内容/历史保留规范。
6. 定向验证事务回滚、幂等、竞争分类、同目录多项目、同ID不同工具、归档后的旧写、只读路径。再用真实 Claude 两个独立会话验证新建与复用，并验收一次性问答无副作用。

## 实施前对抗审查

- 身份：Claude不进入 codex_sources；普通任务回退项目只供阅读，需证据归类才能写。托管任务的已选项目由执行器传入，模型不能用工具参数更换。
- 数据：会话归属版本和档案版本各自CAS；相同请求返回同一结果，不同内容复用ID报冲突；失败不留半份数据库档案。逻辑容器空目录不是已注册项目。
- 兼容：原Codex解析、组织任务和目录仍复用；Codex来源的归类继续走原接口，避免两个权威互相覆盖。
- 体验：无新增人工授权门槛；目录按需读取；不会把全部项目内容塞进每次上下文。页面显示真实归属，不把近期日志活动标成进程存活。
- 质量：结构检查只能阻止不完整提交，不能证明内容正确；真实实验必须逐章核对来源、未知与旧历史。不得手填正式档案冒充模型完成。
- 范围：此阶段不宣称团队调度、节省成本、任意第三方模型或完整发布验收已完成。

审查结论：按以上合同实施；重点观察真实模型能否使用工具完成完整新建与第二会话复用，失败则修正主流程与Skill。

## 真实验收发现的修订

首次 High 实验返回两条HTTP成功但无文字/工具的响应，CLI以success结束，实际无成果、无归类。增加OpenAI适配空响应检测，沿用既有失败收据与禁止自动重发机制。自审：只判定确定的空内容，不把少字、未知模型或合法纯工具回复拒绝；流式与非流式都应覆盖。该实验保留失败记录，换已授权模型的实验是新的明确请求，不伪装原请求重试。

并发审查补充：仅有会话CAS不足以避免两个新会话同时为同一项目建档。新建需提供来自真实项目入口的稳定 project_key（如设计书绝对路径加项目片段）。键由Agent根据证据明确选择，服务不按标题/cwd猜。键唯一、与创建同事务保存；竞争请求发现已有活跃项目时附加会话并要求回读合并，绝不覆盖先提交档案。已归档项目保留历史，重新创建可接替其键。不同电脑路径或错误键仍需要用户/Agent依据目录纠错，不承诺无语义判断的全局自动去重。
