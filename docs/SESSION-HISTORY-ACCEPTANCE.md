# 历史会话查询与阅读：实际验收

2026-09-10，本机工作台已提供“会话 → 查找历史 · Codex / Claude”。这里直接读取已发现的公开会话记录，不需要先创建项目，也不会改变项目归属。近期监看继续以最近任务为主；历史目录按页读取，超出近期128条的任务也可查找。

## 用户怎么用

1. 打开“会话”，点击右上方“查找历史 · Codex / Claude”。
2. 输入标题、任务编号或工作目录，点击“查找”；也可选择来自哪个应用、翻到下一页。
3. 选中任务后先看最新公开消息，点击“读取更早消息”向前查阅。没有公开对话的工具记录片段会自动略过，不会把隐藏推理展示出来。
4. 停在底部时新消息自动跟随；向上翻阅时保持原位置。出现新消息后，可点击“回到最新”。
5. Codex 任务使用原有消息发送入口。普通 Claude 终端提供“复制继续命令”，在原终端继续；工作台不会假装已经向普通终端发送了消息。

同一会话可能有多条历史来源，可展开“任务编号与工作目录”选择原始记录。应用和稳定会话编号决定消息归属，标题相同不代表同一个任务。未发送草稿在本页打开期间按会话保留，切换来源、任务或近期/历史模式不会混在一起；关闭或刷新页面后不保证保留未提交草稿。

## 实测发现并修复的断点

- 初次项目加载完成时，会话页原先被整个重建，打断已经进行的历史查询。全局会话页现使用稳定页面身份，项目相关页面仍按项目隔离。
- 原日志连续若干片段只含工具信息时，“读取更早”原先没有可见变化。现在一次操作会顺序略过空片段，找到公开消息或文件开头即返回；查找较久时让出操作并保留可继续的游标。
- 移动端底部导航挤住继续按钮，已调整历史详情高度。
- Claude 把工具结果装在 user 类型记录中，原投影误显示为用户发言。现在按结构识别纯工具记录，真实用户与混合发言保持原身份。
- 历史页原来在切换任务时丢失草稿，现复用工作台按稳定会话编号保存的内存草稿表。

测试工具自身还修正了两项测量问题：等待目录响应不等于等待页面绘制完成；原锚点保持时，前一个气泡可能在顶部留白里露出一小截，不能因此判定原锚点丢失。最终依据是原消息本身的实际位置，失败记录保留。

## 范围与证据

Codex目录覆盖已发现并登记的来源；Claude目录覆盖配置目录内的可发现来源，发现上限会在页面说明。该入口不代表已经复制所有应用的全部历史，或能恢复磁盘上已经删除的日志。公开窗口仍有单条内容和每次读取的体积边界；它也不证明项目档案已正确整理、所有模型都会采用记忆或多日运行绝不出错。

本机证据位于 `.local-acceptance/`，不随公开发行包发布：`session-history-20260910/acceptance.json`、`session-history-network-20260910/acceptance.json`、`session-history-live-20260910/acceptance.json`、`session-history-drafts-20260910/acceptance.json`。这些目录包含实际截图和原失败记录，不包含对外可使用的通用用户数据。
