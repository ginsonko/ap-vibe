# AP-Vibe 使用说明书

AP-Vibe 帮你保存长期项目的来龙去脉，并把 Codex 与 Claude Code 的任务进展放在一个中文工作台里。你继续在熟悉的任务里说需求；项目资料按章节保存，后续任务按需要读取。本文对应 v0.2.0-beta.1 Windows 个人内测版。

## 第一次使用，做这三件事

1. 让 Codex 按仓库 README 安装。安装会准备本地服务、Skill、MCP 与自动触发脚本；推荐允许整理最近七天的活跃任务。
2. 把需求或图片交给 Codex。比如：“我要长期维护一个阅读记录工具，先设计书籍、进度和笔记的数据结构。”
3. 打开安装输出的工作台地址。首页点任务标题查看进展；“项目与记忆”查看这个工具的资料。

默认地址通常是 `http://127.0.0.1:8765/`。端口被其他程序占用时会自动换一个，请使用启动器打开的实际地址。

## 首页：知道现在发生了什么

首页按最近的可见消息排列任务。绿色活跃状态表示近期有消息，不能单独证明 Codex 此刻仍在生成。

| 操作 | 什么时候用 | 会发生什么 |
|---|---|---|
| 点击任务标题 | 想看完整上下文 | 打开对应任务的会话页 |
| 选择图表时间范围 | 比较最近一小时、一天或七天 | 按已采集消息的时间重新统计 |
| 将鼠标停在图表数据点 | 想知道具体数值 | 显示该时间段的消息数 |
| 刷新现场 | 想立即读取新进展 | 获取最新服务与任务投影 |
| 同步 Codex | 刚有消息但还没看到 | 读取当前项目新增的可见消息 |
| 添加桌面启动器 | 下次不想记地址 | 创建 Windows 桌面快捷方式，复用或启动服务后打开实际地址 |

没有新消息时图表可以为零。服务读取失败时会保留同项目上一次成功数据，并标明尚未更新。

## 会话：按标题接着看

在左侧搜索标题或项目名称，选中任务后，右侧只显示它的已采集消息。消息区域独立滚动，不会随着历史无限拉长。

- 默认看最新消息，位于底部时跟随新消息。
- 向上看历史时保留阅读位置，点击“回到最新”恢复跟随。
- 支持 Markdown、列表、代码块和表格。点击“查找历史 · Codex / Claude”搜索更早任务，进入后用“读取更早消息”向前翻页；缺失日志会说明原因。
- 部分历史存储格式或工具创建的任务不包含可采集的原始用户消息；工作台不会编造缺少的原文。

### 发消息给原任务

填写输入框，点击“发送给 Codex”。支持共享队列的 Codex Desktop 版本会把消息交给原任务；繁忙时排队，完成后回读回复。AP-Vibe 自动发现桌面使用的可执行程序，避免误用 PATH 中的旧 CLI。

“已提交”只表示 Codex 接受了消息，“回复完成”表示取得了实际回复。不要把两者混为一谈。

旧版 Codex 缺少队列能力时，仅能续接已经释放写入者的任务。桌面占用时会保留原消息，提供复制和打开原任务的入口。结果不确定时不会自动重复提交。

## 项目与记忆：每个长期项目一本资料册

一个项目可以关联多条任务。自动发现的工作区只是线索，不会仅凭标题相似就合并项目。

### 有历史时整理，没有历史时直接开始

没有历史项目可以直接提出一个长期项目需求，档案随实际工作建立；无需先整理全部历史。已有项目时推荐最近七天整理，也可以先选当前项目，稍后再处理其它历史。

| 入口 | 作用 |
|---|---|
| 整理最近七天 | 整理近期活跃、尚未归类的任务，适合第一次使用 |
| 整理全部未归类 | 包含更早的历史任务 |
| 重新整理全部会话 | 重新检查项目归属与档案，保留旧版本和人工修改 |
| 更新当前档案 | 只刷新当前已登记项目的资料 |
| 更新全部档案 | 刷新全部已登记项目，不创建项目或移动任务 |

候选加载时显示进度，读取后默认全选，支持反选和清空选择。点击“开始 Codex 整理”即可执行，不需要复制一大段提示词。

整理使用你已经登录的 Codex，会计入 Codex 用量，不需要填写 AP 教师 Key。任务与成功草稿存放在本机；上游失败时旧档案不被清空。可以从原记录继续未完成项目。

### 十一章分别存什么

| 章节 | 内容例子 |
|---|---|
| 项目简介 | 阅读记录工具，给个人读者使用 |
| 用户目标与红线 | 本地保存；未经授权不能上传私人笔记 |
| 逻辑与架构 | 输入书籍 → 校验 → 保存 → 搜索 → 展示 |
| 设计书与资料入口 | README、需求文档、源码和部署说明的位置 |
| 决策与逻辑变更 | 为什么书名不能作为唯一标识，旧方案为何撤销 |
| 完成与待办 | 文档已完成，CSV 导入尚未实现 |
| 风险与十维评估 | 哪些地方已有证据，哪些地方需要继续验证 |
| 验证与新发现 | 重复导入、错误行和中断恢复的验证结果 |
| 依赖与协作 | 服务地址、目录、连接方法；密钥只记存放位置 |
| 当前进度 | 当前阶段、阻碍和事实边界 |
| 恢复与下一步 | 接手时先读什么，哪些步骤不必重做 |

资料有十一章不等于产品已经完成。每章应有能帮助下次接手的真实内容，尚未实现的功能也应明确记录。

新任务先拿到最新目录与版本，再按需要读某一章。默认只带少量与任务目标匹配的观察摘要；旧恢复里程碑和观察正文可主动查询，避免旧待办掩盖最新进度。历史始终保留，查询无须先归类；长期任务写入时才确认它属于哪个项目。

### 雷达图怎么看

十个维度是目标、逻辑、完整性、可靠性、安全性、性能、维护性、兼容性、易用性和验证程度。点击一个维度，可以看到理由、风险、改进建议与来源。

**文字评估与数值评分分开统计。** 如果只有设计文档，没有运行证据，允许保留未知分数；未知不当成零分，也不会补出虚假的图形面积。分数是有来源的项目评估记录，不是模型智力或项目完成率。

### 手动纠正

可以新建项目、修改名称、归档和恢复项目；在历史整理页调整任务归属；在章节中点击“修改这一章”纠正资料。归档保留会话、档案和旧版本。后续整理会保护人工修改。

“原始活动与记忆管理”放在页面下方，平时可以折叠。归档单条活动会改变它是否参与正常召回，原记录仍保留。

## Agent 工作室：按需配置，让伙伴接力

先体验项目资料和换会话续接，再按需要到 **Agent 工作室 → 伙伴与配置** 添加推荐模板。URL、模型和职责已有参考值，API 伙伴填 Key 后可参与；本机 Codex 沿用原登录。可对所选伙伴批量填 Key 或统一 URL，专用连接按各自渠道配置。

打开自动协作后，照常提出有明确产物的任务。复杂工作可以分工，简单小事直接完成。管理伙伴安排计划与依赖，执行伙伴交付文件，独立检查可以接受或要求返工，结果返回原任务。点伙伴查看真实过程与成果，故事回放支持暂停和1/2/4/8倍速。

不开协作也能查询会话和档案；AP教师不需要为协作开启。只有配置保存不代表渠道已经连接成功，首次实际任务会显示结果。普通Claude终端在下次Hook读取返回，不能保证立即唤醒任意终端。详见[工作室说明](AGENT-STUDIO-GUIDE.md)。

## 逻辑观察：用问题带着读代码

初次使用推荐“交给 Codex 分析”，直接说：

> 用户点击开始后，数据经过哪些模块才保存？哪里可能中断？请给出源码位置，并保留旧内容后更新相关档案。

本地静态查询目前面向 Python：选择“它负责什么”“改这里会影响谁”或“预期链先断在哪”，输入项目内相对路径或完整限定名。

例如 AP-Vibe 自身可查询 `ap_mind.studio_server.StudioEpisodeService.run_logic_query`。如果文件匹配到多个符号，继续缩小到完整类名或函数名。

报告显示结论、源码证据、未知项、下一步和历史上下文。静态连接不能单独证明程序运行正确；真实运行结论仍需要测试、日志或结果回读。

## AP 认知：可选实验特色

Vibe 负责结构化资料与恢复，AP 把观察、感受计算、候选行动、选择、回读和经验检验连接起来。页面显示保存下来的过程，让你能检查某次建议是否真的被采用。

基础模式保留本地检索、项目档案、监看及本地运行流程。外部认知教师默认关闭。

开启教师时，填写 OpenAI 兼容地址、Key 和服务商实际提供的模型名称。经过筛选的项目上下文将发送到该服务商，产生网络请求和 API 费用。大型项目可能达到约一元每小时的量级，具体费用以模型、频率和账单为准；请求也可能失败或变慢。

教师可以提出语义召回、预测、感受或范式等候选，但不能直接把建议变成事实。长期学习收益需要持续观察和对照，当前属于实验性质。选择多模态模型也不意味着 AP 已接通图片或音频输入；当前教师接口处理结构化文本。

## 常见问题

**安装了却没有自动读取？** 安装器会复制 Skill、注册 MCP，并为本次安装的 AP-Vibe hook 登记准确的信任记录。运行 `tools/trust_hooks.py` 可回读自身 hook 状态。旧版 Codex 不支持相关接口时，仍可使用 Skill 客户端；不要信任来历不明的其他脚本。

**要每条任务自己绑定吗？** 不需要。任务按已有归属和真实项目资料自动处理；长期项目由 Codex 按标准流程建档或更新。普通问答、公告等一次性任务不用建成长期项目。

**服务不在线怎么办？** 双击桌面启动器，或让 Codex 使用安装配置恢复服务并打开实际地址。服务故障不应阻止原任务；未写回的档案可以保存为带请求编号的补丁，之后安全重试。

**整理失败，旧资料会消失吗？** 失败草稿与既有档案分开保存；项目刷新不会清空旧档案。涉及版本冲突时要合并最新内容，不能强行覆盖。

**会自动让模型越来越聪明吗？** 已保存与已读取不等于已经产生收益。应看具体采用了什么资料，是否少了一次重复解释、返工或错误；长期收益暂不作保证。

**能商用吗？** 当前许可证禁止商用，允许个人二次开发和免费分享，并要求保留来源及许可证。商业用途需要另行授权。


## 把项目资料带到另一台电脑

1. 在原工作台打开“项目与记忆”，选择项目，点击“导出当前项目”，保存JSON。
2. 把代码或设计文件单独复制到新电脑。打开新工作台，点击“导入项目”，选择JSON，填写此电脑的项目目录。
3. 预览章节、十维分析和来源版本，点击“创建副本并导入”，然后“打开导入的项目”。

例如设备借用登记项目：复制文档到 `D:\我的项目\设备登记`，导入时填写这个已有目录。导入创建独立副本，原项目保留。旧决定、事故、备注和待办随当前章节保留；原有未知分数仍为未知。不要把11/11章理解为所有功能已经实现。

发生网络中断时可直接重试同一次导入；刷新页面也会保留待完成的确认。旧格式包没有档案时，预览会明确说明，推荐在原工作台更新后重新导出。导入历史摘要可在项目页单独展开，它们不会伪装成新会话活动。

这不是整机备份：包内没有密钥、源代码、完整会话、所有旧版本或正在运行的伙伴。路径经过脱敏，迁移后让Codex补充新目录。可以说：“请读取这个导入项目的简介、资料入口和恢复章节，核对此电脑的实际目录，增量更新变化，保留旧决定与事故。” [实际验收范围](PORTABLE-DOSSIER-RESULTS.md)
