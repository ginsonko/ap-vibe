# 伙伴实测表现与首次工作流对照

2026-09-10，工作室新增“实测表现”，数据来自持久运行和实际验收。不是按模型名字预填的能力分，也不调用额外模型生成评分。

## 能看到什么

- 按时间、任务类型、伙伴和配置范围筛选；历史配置保留各版样本，未测试的当前配置显示未知。
- 运行次数、不同逻辑任务数、独立通过/需修改、其他检查记录、执行失败/不确定、真实执行耗时和已知费用。
- 独立裁决必须对应作者运行，并包含检查项和文件哈希。验收员“报告已应用”单独计数，不当作它的评审能力获得独立验证。
- 费用展示已知部分及未知次数，CLI估算不等于供应商账单。缺金额不计作免费，等待人工检查不算执行耗时。
- 点开具体经历可以看理由、检查项，再进入原任务与实际成果。刷新不会启动模型。MCP的伙伴目录提供短摘要，`ap_vibe_agent_metrics`按需提供细节，所有接入会话均可读取。

实际本机窗口在本阶段结束时包含66次运行，其中43次有金额、23次未知；独立结论8次通过、1次需修改。该窗口含研发验收、失败请求和归档角色，不是用户生产效率或真实账单统计。数据随新工作自动变化。

## 真实单人与团队对照

使用之前相同八条合成销售数据，输入SHA相同。新任务由一位作者完成金额、异常和中文报告，随后一位独立验收员检查；之前团队由规划者创建两项并行任务、各自检查、汇总并再次检查。

| 本次观察 | 单作者与最终检查 | 之前团队流程 |
| --- | --- | --- |
| 真实模型运行数 | 2 | 7 |
| 从登记到最终裁决 | 263.77秒 | 742.54秒 |
| CLI估算费用 | 1.755180 USD | 10.338590 USD |
| 金额核对 | 23500 cents | 23500 cents |
| 异常行 | row3、row5、row8 | row3、row5、row8 |

新作者与独立检查均完成，没有手填成果。再次读取实际JSON核对纳入/排除行、总额、异常与原输入SHA；能力接口的运行数、独立通过数和金额也与原执行收据逐项一致。

这是不同时间运行的单次小任务观察，服务负载、提示和流程不同，未随机化。团队流程的规划、沟通、多次检查开销被完整计入，不能用它宣称某个模型普遍更快、更聪明。最直接的设计结论是：边界很小的任务优先单人完成；存在充分独立工作、明确验收和实际收益预期时再拆分。复杂任务能否获得净效率收益仍需进一步测量。

回看之前团队的实际中文报告，还发现它把未指定币种的cents举例解释为“元”；虽写了“若按人民币习惯理解”，后文直接给235.00元，容易让读者误解。此前独立检查也放过了这个问题。因此两个流程的金额与异常行可以直接对照，文字解释质量不能宣称完全等价。新任务明确保留输入单位且不猜币种。原报告与原裁决作为历史证据保留，后续规划/验收补充单位、币种及假设依据检查；独立验收记录仍然可能包含判断失误。

## 验收与边界

20项定向检查覆盖归因、检查者误计、费用未知/非有限值、返工去重、85条历史分页、配置版本、标签、覆盖上限和重开；19项既有安装/插件/Codex执行器/任务池检查通过。前端构建成功，仍有现有单文件包超过500KB提示。

真实浏览器在1440和390宽度逐项点击了时间/类型/伙伴/配置筛选、显示归档、无样本、职责编辑入口、安排工作入口、原成果跳转、分页、帮助、刷新和失联后的缓存恢复；没有发起模型任务。修复了复选框被输入框样式撑宽、头像外框缩小但内部图集没缩小、原运行超出最近80条时详情被列表刷新挤掉的问题。最终无页面错误、无页面横向溢出、头像不遮挡文字。

本机私有证据：`.local-acceptance/browser-metrics.json`、`metrics-1440.png`、`metrics-390.png`、`single-sales-20260910-v1-acceptance.json`。原始会话与连接不随仓库发布。完整角色动作、真实素材委托、复杂任务效率与最后全站安装发布仍在推进。
