# 角色动作与交流演出计划

2026-09-09。接续 MAP-PLAN 和 revision41；整体产品目标仍未完成。

## 输入与交付

已有九位原创静态角色、持久运行现场、PNG/JSON图集导入、六房间地图和消息API。用户授权使用银子媒体工作流生成动作，要求模型家族辨识度、可配置外观、真实状态驱动和低操作成本。

本阶段交付：先制作DeepSeek一套参考身份一致的动作图集，检查合格后扩充；本地通道移动与真实消息演出；用户从伙伴配置发起制作素材任务的入口。代码与素材合同保持分离，运行调度不依赖动画。

## 实现顺序

1. 保留原媒体会话、节点、失败与回执。新动作是新语义请求；generation37/41/64不重放。先上传已有原创角色到本地媒体目录，生成一次4列8行图集：前/后/左/右走路、工作、阅读、说话、休息。每行4帧。按实际输出裁切、去背景、统一脚底与比例，保留源文件、哈希和动作完整性结果。不把翻转静图当走路。
2. 素材版本独立于模型路由。旧静图保持可访问，新动作使用新外观ID；动作方向优先精确匹配，缺少动作显示idle，系统减少动态时停止切帧。
3. 地图导航使用可替换的节点和连边JSON。房间内空地接中央房门，经横向走廊移动；中途改任务从当前位置重规划。采用已有最短路库。初次加载直接呈现现场；失联冻结；恢复按最新位置/目标继续；快速状态变更以最新目标为准。
4. 从已保存消息中读取轻量事件。首次快照仅标记水位；新消息按message_id去重，以本地有限时长演出走近、说话和返回。消息先真实入库，动画失败不重发、不改变已读状态。筛选掉、离开视野或已归档的对象不虚构在场，仍在消息列表可查；密集消息合并展示计数，可展开原文。
5. 从配置页提供“请伙伴制作外观”任务入口，带上角色要求、现有参考、PNG/JSON合同、验收要求和导入路径；进入现有任务安排流程选择真实执行伙伴，保留URL/Key配置隔离。

## 对抗性审查

| 风险 | 处理与验收 |
| --- | --- |
| 生成图集不对齐、动作重复、身份走样 | 首套逐行放大及GIF实际观察；检查帧数、透明边、脚底、像素差异。失败记录缺失，不冒充合格，不批量浪费请求。 |
| 像素图移动穿墙、任务变化半路瞬移 | 拓扑与地图一致；穿房间只走门；路径含中途位置；浏览器记录中间位置与动作帧。 |
| 名称/气泡覆盖按钮或出界 | 固定角色盒、限定气泡尺寸、地图边缘夹紧、点击进入原消息；桌面/手机及长文本验收。 |
| 重连/重复轮询回放旧消息 | 初始水位+message_id去重；断线恢复补最近而不重播历史；不调用发送API。 |
| 用户以为气泡代表已读、模型思考 | 标明“工作消息”；只显示公开保存文本；不推断情绪/私密思考/已读。 |
| 动画拖慢后台或失联仍假装工作 | 动画只有浏览器本地时间，后台任务无依赖；失联及隐藏页暂停；减少动态有效。 |
| 新素材破坏旧任务外观 | 新版本ID、旧资源不覆盖；选择新外观后仅影响新配置/新任务。 |
| 自定义素材与新方向不兼容 | 方向作为可选动作名，按基础动作/idle回退；旧单图继续工作。 |

审查结果：按以上边界实施，无需新增用户确认。媒体超时保持原请求和费用未知事实，按回执恢复。整体发布仍须普通跨应用接续、规划MCP/能力比较、全站与干净安装验收。
