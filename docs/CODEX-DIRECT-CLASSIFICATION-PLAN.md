# 普通 Codex 当前任务直接归类

真实演练已自动选择Skill、写完设计文档并进入收尾，但共享ap_vibe_classify拒绝Codex，要求走旧organization；这是按执行器类型硬编码的断点。历史批量整理继续保留，当前单任务不应被迫新建批量任务。

设计：复用现有TaskProjects事务，使Codex也能查询已注册目录、按真实入口新建完整11章/十维档案或附加已有项目。会话membership与当前Codex来源一起提交，保留所有旧活动、游标和归类撤销历史。新来源发现时读取同一membership，手动归类同步已有membership版本，防止UI/Skill两套身份分叉。没有日志文件的真实会话仍可归类，日志稍后出现时接回；读取仍不需要归类。

对抗审查：原本的项目key并发复用、请求幂等、CAS、只读身份保护、托管指定项目约束继续使用；新建必须完整档案，不能把自动来源容器当成已注册项目。任何中途错误回滚档案、归属和来源赋值；两个运行器即使session文本相同也相互隔离。手动纠正后旧写收据失效，历史可读；归档不会被自动复活。新source继承归属仅凭精确session_id，禁止按名称或父目录猜测。

验收：Codex新建/第二会话复用、来源后到与多份rollout、重复请求、人工纠正、事务回滚、归档后的重新归类以及原Claude回归。然后恢复原真实演练的同一session，使用新的语义请求收尾，不由主任务填档案，不重新执行已完成业务文档。第一轮远程扩展超时和第二轮归类失败/有界终止全部保留。
