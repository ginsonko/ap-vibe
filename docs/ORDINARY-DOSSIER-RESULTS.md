# 普通 Codex 任务的真实项目档案收尾

2026-09-10，在独立中文需求项目“离线设备借用登记”中，原始任务只要求读取 README、写四种错误情形说明并回读。业务提示没有规定 AP 工具调用序列。安装的 Skill 自动被选中，实际任务最终自行完成项目归类、11章保存、十维分析、逐章回读和采用反馈。

这不是首次无干预成功。第一次因远程扩展加载超时没有完成；第二次写完业务文档后，AP-Vibe 的旧接口错误地拒绝 Codex 直接归类。两次都到达有界时限并保留原请求。修复执行器归类分支、同步 Skill 后，在同一 Codex 任务中发出新的接续说明，第三次退出码为0。原有业务文档没有重写。

实际工具顺序为 context → projects → read → classify → context → 分四组 read → feedback。新的独立项目保存为第1版，11章齐全。十维都给出了各自理由、风险、改进和证据范围；项目只有设计，没有程序，评分全部为未知。没有把“齐全”解释成已经实现或已经高质量。

保留内容包括：设备使用稳定编号、同名设备允许、重复借出限制、未知归还日期留空、D-1决定、I-1旧事故及撤销规则、用户关于下一阶段CSV的备注、未实现功能和恢复入口。独立回读确认 README 和业务文档哈希没有变化，服务重启后11章内容相同，真实来源任务仍属于这个项目。

浏览器逐个查看11章目录与十维理由，通过任务页面确认关联身份。任务本人记录“没有证明额外记忆收益”；本次只能证明修复后的普通任务具备真实建档和收尾能力，不能推广成任何模型、任何机器都必然自动完成。

继续内测关注：普通新任务首次使用体验、外部连接器超时、任务规模增加后的维护成本。已经完成的请求无需重放。
