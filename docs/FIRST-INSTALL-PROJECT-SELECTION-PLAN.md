# 首次打开与项目失效后的自动选择

真实独立安装使用自定义项目 clean-install-demo。前端仍以 ap-vibe-local 发起 state/data 请求，服务返回项目不存在，所有页面反复提示重新连接。安装和 hook 成功未覆盖这个断点，当前浏览器截图作为失败证据保留。

修复：本次目录响应是项目存在性的依据。首次打开不预设项目 ID；保留存在于实时目录中的已选项目，失效则优先选择服务实际配置的启动项目，然后选择实际活动的已登记项目，再回退到实际活动来源。项目请求必须等待目录核对，通过现有请求代际控制切换；失效 ID 不发送项目数据请求，不将其错误混入新项目。无项目时只显示空目录，全局监看仍可用。选择只影响浏览器，不改归类或档案。实际主工作台含多个登记项目，不能把字母排序的首项误当成启动项目；以真实 health/目录提供的配置为依据。

对抗审查：自定义中文安装路径、旧 localStorage 中已删除 ID、冷打开、刷新保留选择、A/B/A 快速切换、目录请求失败、空目录都必须合理处理。网络失败不能当作目录为空而跳到别的项目；慢旧请求不能覆盖新项目。优先复用现有选择清理和代际取消机制，不添加手工绑定或确认步骤。

验收：在同一隔离实际安装上更新前端；浏览器冷打开和失效偏好打开都不再请求不存在项目，不出现重连错误，并实际读取目标档案。主工作台的真实去重标题和来源导航继续检查。升级须保留原端口、独立配置、用户自定义 hook/MCP/Skill 和项目资料，结束后正常停止隔离服务。浏览器初次导航截图未等待页面异步数据的项，只作为发现线索，不当完整验收。
