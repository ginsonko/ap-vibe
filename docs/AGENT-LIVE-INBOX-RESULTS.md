# 工作进行中补充信息：真实采用验收

2026-09-10，分别给 Claude Code 执行的 Grok 和本机 Codex 安排一项小型订单汇总。初始数据为 A 已付款 1000 分、B 已付款 2500 分、C 已取消 999 分。两者开始执行并出现工具事件后，从工作台的协作看板实际发送“B 已退款，不计收入；币种仍未知”。这条新事实没有写在初始任务里。

两个真实运行均在上下文工具返回中获得新消息，并在计算前、交付前读取增量收件箱。它们交付的 JSON 均为：合计 1000 分、只计 A、排除 B/C、币种 null；更正附有各自真实 message_id。主任务读取了源码、JSON 和报告，复制脚本到独立目录实际重跑，结果相等，原文件 SHA 保持不变，随后记录本次验收通过。

| 路径 | 实际执行 | 进行中消息 | 最终采用 |
| --- | --- | --- | --- |
| Claude Code / Grok | 本地 Python 汇总与结果回读 | 页面发送退款更正 | 合计由原数据的 3500 调整为 1000，记录来源 |
| Codex | 本地 Python 汇总与结果回读 | 页面发送独立更正 | 同样采用，计算前和交付前增量读取均无进一步消息 |

浏览器还模拟了“服务已保存消息，确认响应丢失”。重试沿用同一请求编号，返回同一个消息 ID，没有重复保存。一次验收脚本的相对 URL 错误发生在消息保存之后，后续只做回读，保留原错误，未再发送。Codex 最初带有其 CLI 不支持的轮数参数，在创建运行前被拒绝；修正后只启动了一次真实任务。

产品改动包括：有序增量收件箱、同任务和收件人筛选、MCP 工具结果附带新消息、错误时保留原工具成功结果、逻辑任务消息气泡正确归属；前端把发信表单置于顶部，选任务即确定伙伴，普通多人留言单独说明用途，历史使用独立滚动区域。

传输和模型采用分别验证。四项新增本地检查覆盖超过一页的消息、进程重启、真实 stdio、断线恢复和事件隔离；原协作/MCP/执行器相关检查也通过。1440 桌面与 390 手机均实际操作、保存截图并查看。Skill 已同步到本机 Codex 和 Claude 安装，用户原设置保留。

这一结果证明这两个小任务能够使用进行中补充的事实，不能外推所有复杂任务必然成功或更便宜。Claude CLI 返回约 1.268745 美元估计，Codex 未返回金额，实际供应商账单均未知。长时间等待模型、仅连续使用原生本地工具、最后一次读取后到达的消息仍有延迟；Skill 要求自然阶段及交付前读取，不使用高频模型轮询。普通非托管会话可以按真实 run_id 查询，结束的任务不会因为收信被偷偷重启。
