# 任务列表按需详情

问题：工作室每4秒拉取最近80次运行的完整快照，含长提示、模型结果和任务定义。当前响应已超过任务客户端2MB读取预算，查询所有运行报错；浏览器也反复处理无用正文。

设计：HTTP无run_id时默认返回相同80条运行的摘要，包含稳定ID、实际状态、伙伴/项目、依赖、标题、有限目标、版本和详情URL；指定run_id保持完整内容和事件游标。需要原协议完整列表时可明确compact=false。数据库、内部调度器的完整runs读取和存量记录不修改。前端已有详情请求继续复用，不增加用户点击。

对抗审查：摘要是投影不是截断原资料；状态、依赖和选择任务的ID不得变化，不能把丢失费用计成0。完整错误、提示与验收报告仍在详情。默认80条范围明确，不能作为全部历史计数。验证超大合成提示、HTTP默认/显式完整/指定ID以及真实浏览器选择与轮询保留详情；实际体积同批比较。不得为了测量启动模型或改原成果。
