# 制作任务的可插拔工具接入

## 当前断点与目标

“请伙伴制作外观”已有真实参考、图集合同和任务入口，但托管Claude仅有AP-Vibe MCP与读写工具；无法调用已安装媒体工作流，也无法执行本地图集处理。提示词准备成功不代表制作成功。

在现有任务上添加明确的extensions字段。制作外观自动选择yinzi-media，任务表单可取消。任务池与续办/交接保留选择，历史运行冻结实际启用的扩展。默认任务不载入媒体工具。

扩展从本机已安装的工作流插件和runtime注册表发现，允许环境变量覆盖安装位置；不读取模型Key，不复制全局连接设置，不写死个人路径/端口。Claude加载同一个插件的Skill与MCP，Codex读取同一Skill并挂载同一MCP。带媒体扩展的Claude开放本地Bash用于PNG处理与实际验收，工作仍限定当前成果目录；这不是OS安全沙箱，不能声称防止任意系统访问。

未安装扩展或运行注册表缺失时，给出真实缺口与可继续的本地工作，不阻断上下文、档案和已有成果。外部生成遵守用户授权与媒体工作流自己的幂等和对账协议。登记扩展不产生付费调用。

## 对抗审查

- 旧任务幂等哈希必须保持兼容：空extensions不添加哈希字段；有扩展的请求纳入哈希，冲突不能悄悄启用新工具。
- 续办和交接没有显式选择时继承原运行，避免恢复后工具丢失；独立验收默认不继承付费制作扩展，验收只需原成果。
- 复制插件仅包含代码/Skill/参考，不复制用户模型配置。MCP与CLI绑定同一已登记loopback地址，不能因默认连接空白创建新媒体任务。
- 任务池更新缺字段不得删除原扩展选择。旧API客户端无需增加字段。扩展不可用必须在运行事件和上下文中明确，不伪造已接入。
- 定向测试覆盖启停选择、缺安装、路径空格、端口、幂等、续办/交接与任务池传递；实际托管任务检查Skill、工具、文件和回读，不能只检查提示词。

审查结论：在现有执行器入口上小范围接入。先验证本机发现/无费用读操作和PNG处理，再验收真正委派制作。整体发布与效率目标继续保留。

## 真实验收发现与修订

首个Grok运行确实加载Skill并调用媒体get_session，但原任务返回3666行完整历史，模型连续多轮顺序读完，延误了PNG处理。这证明“工具可用”仍不够。

为托管任务增加stdio结果投影：get_session默认提供session身份、状态、revision、节点小目录及素材索引；完整原响应以内容哈希保存在本任务工具结果目录，可按需读取。可用node_keys只展开指定节点。透传执行工具，不重试、不新增模型请求、不改变媒体服务数据库。原始响应、来源、失败与未知状态均保留。审查重点是投影不把缺字段解释为成功，且节点版本/ID/来源入口足够下一步操作。

第二个真实任务需要猜外观GET路径并遇到404。补充现有外观API的标准MCP入口：ap_vibe_appearances只读目录，ap_vibe_appearance_import读取本地PNG/JSON后提交现有不可变保存接口。图片字节不进入模型参数或工具输出。无档案身份门控，重复导入沿用内容ID；多角色manifest要求明确选择，不猜其中一个。不增加另一套素材存储或配置。
