# Agent 工作室：真实基础实验记录

日期：2026-09-08。状态：基础实验预览，尚未达到完整团队协作或公开内测发布标准。本文保留失败样本；模型名称指用户配置及服务接收的模型 ID，不能独立证明供应商内部模型身份。

## 当前可亲自使用的路径

打开本机工作台的 **Agent 工作室**，添加伙伴或复制已有配置；填写名称、服务地址、Key、模型，选择参考项目并安排一个独立小任务。可以查看公开消息、工具调用和执行结果，检查成果后记录验收结论，也可以继续同一会话处理下一步。

Key 在本机加密保存，不会回填到表单。复制配置在服务端复用已保存的 Key。每次任务保留当时模型/配置版本、独立运行 ID 和成果位置；接续保留原 session 与目录，使用 Claude CLI 的 `--resume`。每个新回合有独立收据。修改了角色配置后，旧会话接续暂不自动切换模型，需使用新任务。

任务目录用于工作成果隔离，**不是操作系统沙箱**。当前预览开放读取、写入、编辑、搜索文件以及 AP-Vibe 按需只读工具；尚未开放通用 Shell、自动部署或任意工具执行。执行器完成后可以继续，无需先人工验收；验收按钮用于记录对具体成果的检查，不是读取项目资料的门槛。

### 并发执行成功，内容仍需返工

两个 High 伙伴同时写新手说明与排障清单。最初只要求读取 identity/status 两章，足以恢复项目大意，却缺少详细操作依据；模型未把这些缺口标为未知，反而把“未验证”写成“未实现”，并把重叠请求混同成重复任务。两份原文因此都记录为 **需要修改**，没有为了实验通过而直接验收。

后续将具体错误、实际功能说明和伙伴草稿交给原会话定向返工。它能读取这些资料并修改文件，证明了可由外部审查者指导的接续修正；这尚不是自动团队通信。第一次返工仍有范围表述不准，再次针对两点纠正。最终 `run-9c07a192c26141c0ab6332338c758ccd` 真实完成 Read/Edit/Read，经 Codex 直接读文件后通过工作台记录验收通过。失败草稿、审查结论与新回合记录均保留。

本场景支持 F05 的同模型并发和 F06 的名称配置快照隔离；两个不同服务/Key 的完整并发隔离还未由本实验覆盖。也没有单 Agent 同题基线，因此不能由并发墙钟时间或工具成功直接发布省钱/提速比例。

## 从失败中修复的具体问题

1. MCP 漏填参数时曾只有笼统错误。现在返回具体缺失字段，提示模型补全，不代填虚构的任务目标。
2. 工具结果原先不显示。现在展示完成/失败及脱敏错误，避免页面只显示“正在执行”却看不出循环。
3. 普通文本和工具结果按兼容格式转换；图片混合内容保留结构。原生 Messages 也经过同一个本地可观测网关。
4. 原响应等待为固定 120 秒，现为用户可配置，默认 300 秒。复制伙伴保留响应等待设置。
5. 仅在上游失败后拒绝重试不够：CLI 可能先超时并发重试。现以每运行一个在途请求识别重叠提交；拒绝的请求不发往上游。原请求完成后正常新回合可运行，这不是调用次数上限。
6. HTTP 200 的错误包与缺失流终止不会记作成功。断开连接后保留不确定结果，已有成果不删除。
7. 服务重连后自动清除对应的旧连接提示，保留已有列表/消息和真正的操作错误。角色卡按当前配置的真实近期运行显示返回成果数与验收数。
8. 窄面板点击任务或开始执行后定位到输出，点击接续定位到输入；后台刷新不抢滚动位置，尊重减少动态偏好。真实浏览器截图已确认选中任务后输出进入可见区域。
