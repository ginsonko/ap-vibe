# 经济分工与真实经验

协作已开启时，复杂目标先拆出边界清楚、值得委托的工作。按需给伙伴资料入口与完成标准；不复制全部历史，不为小任务增加规划、审查和唤醒成本。

先读 `ap_vibe_agents`，再用 `ap_vibe_agent_recommendations({tags:["frontend"]})` 查看同类排序；可选 eligible_agents 限定用户允许的人选。无MCP仍用task_client.py tool同名入口。没有这个新工具的旧服务，可按已配置role和实际metrics继续，不能因建议接口不存在停止原任务。

默认印象可在伙伴编辑的“分工简历与费用偏好”修改：Grok负责明确杂活，Gemini偏文案和友好体验，DeepSeek偏推理/数学/规划，Kimi偏前端，GLM偏简单代码，Astra/Codex偏关键规划和最终确认，CC Max偏困难攻坚。Kiro与CC Max分渠道、分伙伴积累。同家族不保证同渠道效果，初始匹配数字不是测得智力或成功率。

工作tags写可复用类别：routine_code、frontend、writing、research、reasoning、planning、review；困难或核心可靠性加critical/complex/hard。随机批次号不应充当类别；在简历增加任意自定义工作类别后可按该标签积累。用户明确指定优先，未知模型不禁用。

同类、兼容执行配置、经过可归因验收的逻辑任务形成经验。独立文件裁决权重1，普通原任务的署名裁决权重0.5；自报、运行退出、网络错误不算质量通过/失败。一个逻辑任务的重试只合并一票；最终通过但有返工保留折损。审查报告被应用不等于审查者自己的能力已验证。

经验权重为 n/(n+k)，默认k=6且用户可改。1个有效样本约14%，6个50%，24个80%；没有同类样本沿用可编辑简历。改变模型、地址、协议或Key后从新的执行配置重新积累；改名、人设、职责不抹掉经验。旧配置未经证明不能强行迁移。默认高价对常规任务降低优先级，关键任务可正常选择；不是调用门控。

价格和能力独立：未知价格不代表免费。历史已花金额除以完整记录token可得混合参考价，不能唯一解出输入/输出/缓存单价。使用price_basis=blended并注明日期、范围、用量缺失和账单覆盖，保留用户上限。后续按参考价估算，旧请求价格不重算；充值不是已发生费用。
